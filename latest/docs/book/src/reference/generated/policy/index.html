Palisade policy document

A versioned policy document: one policy and the rule sets it uses.

Schema: schemas/policy/v1.json ($id https://github.com/jusso-dev/palisade/schemas/policy/v1.json), version 1.0.0. Regenerate the schema with PALISADE_BLESS=1 cargo test -p palisade-policy --test schema, then these pages with cargo xtask docs generate.

Fields

FieldTypeRequiredDefaultConstraintsSinceDescription
policyPolicyyes1.0.0The policy.
rule_setsarray of RuleSetnoat most 1000 items1.0.0The rule sets the policy references, in any order. The policy's rule_sets list gives the order that applies.
schema_versionSchemaVersionyes1.0.0The version of this schema the document was written for. A reader accepts the same major version and any minor version.

Object types

  • Action: The action of a rule (#34).
  • ClientFilter: The client connected to a remote desktop session, for per-client scoping on multi-session hosts. Each list that is set must match.
  • CloudObject: An object in a cloud directory: a group of users or of devices.
  • Criterion: A test of one fact about the object or its context: field operator values.
  • DateRange: An inclusive range of dates. to unset means the single day from.
  • DeviceRef: A device or group of devices (#38).
  • DirectoryGroup: A directory group.
  • Effects: The effect flags of one rule. Unset fields take the action's default.
  • GovernanceSettings: The tenant's governance settings (#40). Every field is optional.
  • LibraryRef: A reference to a library from a match tree or a hierarchy assignment.
  • LocationProfile: A named network location, such as corporate: every test must match (#38). The agent evaluates the profiles when the network changes and on every heartbeat, and scopes test the result with location_profile.
  • Match: A condition tree (#33).
  • Metadata: Governance metadata (#40), on a policy, a rule set or a rule. Every field is optional. Metadata is not decision-relevant: it never changes what a rule decides (PolicyDocument::decision_relevant).
  • ModeOptions: Mode settings besides the base mode. Each is optional in a document.
  • NetworkRef: A network location test (#38). Address tests match when any local interface address does.
  • OnExpire: What happens when a rule expires.
  • OuRef: A directory organisational unit.
  • Policy: The decision part of a policy: which rule sets apply, and how.
  • PolicySettings: Settings that apply to the whole policy. Every field is optional in a document and has the default shown in the schema.
  • PrecedenceOptions: Settings of the precedence models. Each is optional in a document.
  • PrincipalRef: A user or group (#38). Each is an object with one key, the kind.
  • PromptSettings: How the prompt level asks the user.
  • RefList: An include and an exclude list. An empty include means every entry; a match in exclude always wins.
  • RefList2: An include and an exclude list. An empty include means every entry; a match in exclude always wins.
  • RefList3: An include and an exclude list. An empty include means every entry; a match in exclude always wins.
  • Rule: One rule: a match tree and the action taken when it matches.
  • RuleSet: A named, reusable, ordered collection of rules.
  • RuleSetScope: The scopes of one rule-set assignment: every one must match for the set's rules to apply.
  • Schedule: When a scope is active (#38).
  • Scope: Who, where and when a rule applies (#38).
  • ScopeLimit: One contributing policy's limit on where its unknown settings apply, in an effective policy (UnknownPolicy::scope_limits). It holds when every scope of all_of matches and, if any_of is not empty, one of its scopes matches.
  • SessionFilter: Session criteria (#38).
  • SignerOptions: The options of a signer criterion (#31).
  • UnknownPolicy: The unknown-application policy (#39). Every field is optional in a document; the defaults block every unknown object.
  • Window: One weekly window.

Enumerations and string formats: Value types.

Examples

Each example passes this schema and full validation (cargo test -p palisade-policy --test yaml, in CI).

  • actions-and-effects.yaml: Rule actions and effect flags (#34). Each rule set kind holds the actions it is for; a mixed set holds any. Effect flags are optional: an unset flag takes the action's default (see the palisade-policy README).
  • context-criteria.yaml: Context criteria narrow an identity: who runs the object, where and when (#32, #33). Every rule still names the object by a hash, signer or path; the context only narrows it.
  • finance-workstations.yaml: Finance workstations: allow one line-of-business suite by publisher, product and minimum version, and keep PowerShell in audit while scripts are reviewed. signer.publisher is the signer's common name (the CN of the leaf certificate's subject), not the whole distinguished name.
  • first-match.yaml: A firewall-style policy: rules are ordered, and the first rule that matches and does not defer decides (#35). Curated rule sets come first (curated_first, the default). The mandatory blocklist is checked before every ordered rule, whatever its order.
  • minimal.yaml: The smallest valid policy: no rule sets, so nothing is allowed and every file is reported (audit mode) by the implicit deny.
  • rule-lifecycle.yaml: Rule lifecycle and governance (#40). Governance mode is on, so every allow carries a justification and a review date, and the exception (a path allow for a vendor tool) also carries an expiry within a year, an approver and a risk rating. A temporary deny becomes an audit rule when it expires, so its matches are still recorded.
  • scoped-rules.yaml: Rule scoping: who, where and when a rule applies. Scopes narrow a rule; they never identify the object, which is the match tree's job, and they never widen a rule. A rule applies only when the policy's scope, its rule set's assignment scopes and its own scope all match.
  • staged-rollout.yaml: A staged rollout (#36): the policy is in audit, so what it would block is reported but runs. Executables are already enforced, a disconnected device enforces everything, and a new blocklist is tried in monitor mode. The mandatory blocklist blocks in every mode, and one deny rule is enforced in audit too (always_enforce).
  • unknown-applications.yaml: Unknown-application handling (#39), starting from the Essential Eight maturity level 1 preset: unknown objects in user profiles, temporary folders and other user-writable locations are blocked, and elsewhere they are detected.
  • workstation-baseline.yaml: A workstation baseline with hash, publisher and path rules (ISM-0955). The same document as tests/fixtures/valid/workstation-baseline.json.
