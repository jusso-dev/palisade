Module counters 

Source
Expand description

Per-rule hit counters (#40).

Counters holds one slot per rule of an Evaluator, indexed by the rule’s ordinal (its position in the evaluator), so recording a hit is one relaxed atomic add, with no lock and no allocation. The last match time and the sketch registers are read first and written only when the value grows, which after warm-up is rare. The agent records every terminal match and annotation (Counters::record) and takes a HitReport every counter_report_hours and on a policy change (Counters::report).

The per-decision cost is Counters::hit_key with the rule’s ordinal, which the agent looks up once per compiled rule (Counters::ordinal, Counters::ordinal_of) and keeps with it; Counters::record is the convenient form, with an O(log n) lookup per rule of the decision.

Counters belong to one bundle revision. A report carries the policy ID and revision, and the server adds reports up across revisions by rule ID. Reports serialise with the sketch registers (as hex), so the server can merge them and the agent can store them. To survive an agent restart, the agent stores a snapshot (Counters::snapshot) at shutdown and Counters::restores it into the new counters of the same revision: the totals carry on, and hits that were not yet reported are reported next time, never twice.

distinct_objects is a HyperLogLog sketch with 1024 one-byte registers (1 KiB, a standard error of about 3%), updated with atomic maximums. distinct_devices is the server’s sum of these sketches across devices (#10), so it is not kept here.

The HyperLogLog estimate of a sketch’s registers, with the small-range correction. None unless there are 1024 registers, each at most 55.

Merges sketches, as the server does across devices for distinct_devices and across revisions: the register-wise maximum. None if any sketch is malformed.
object_key
The key Counters::hit_key takes for an object: a 64-bit hash of its identifier (its SHA-256, for example). FNV-1a, then a finaliser, so any identifier spreads evenly over the sketch’s registers.
