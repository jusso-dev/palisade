palisade_policy::bundle

Module format 

Source
Expand description

The bundle’s byte format (#43): a header that decodes on its own, then the body.

A bundle is one canonical CBOR array of two items, [header, body]:

  • the header names what the bundle is for and when it may run: format and schema version, tenant, target, policy_version, min_agent_version, generated_at and an optional expires_at. decode_header reads it without reading the body, so the signature envelope (#225, in palisade-proto) can check the target and version cheaply. It is safe on untrusted input;
  • the body is the effective policy, the library sets its scopes use, the source revisions and the digest of the governance metadata that stays on the server.

Every map key is a registry ID. The encoding is canonical at two levels: the CBOR is deterministic (super::cbor), and the body is in canonical order (Body::new: rule sets, rules, assignments and profiles sorted by ID or name, governance metadata removed). PolicyBundle::decode refuses input that is not in that form, so one content has exactly one byte string, and bundle_hash identifies it.

PolicyBundle::decision_hash covers only what decisions depend on, for the decision cache (#42): it leaves out the header, the source revisions, the metadata digest, the policy revision, and every name, description and display-only field.
