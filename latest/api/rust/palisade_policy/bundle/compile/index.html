palisade_policy::bundle

Module compile 

Source
Expand description

Compiling a bundle from a policy (#43).

compile takes a ValidatedPolicy, usually the flattened policy of an EffectivePolicy (inheritance already merged, match-tree references already expanded, scope set references pinned to versions), and the library catalogue those pins name. It inlines every library set a scope or location profile reads, pins every reference to the version inlined, records the sources, builds the canonical body, and reads the result back as an agent would. Nothing platform-specific is precompiled: the agent builds its indexes when it loads the bundle (#42).

BundleSets is the inlined sets as a ScopeLibrary, so a loaded bundle evaluates with exactly the sets the server compiled in.

Structs§

BundleSets
The library sets inlined in a bundle, as a scope library. compile pins every reference, so a reference resolves only at a version the bundle holds; a latest reference, which a compiled bundle never has, resolves only when the bundle holds exactly one version. Anything else is unresolved, so a scope that needs it is unknown, as with a missing set.
