Module delta 

Source
Expand description

Deltas between two bundles (#43).

diff describes how to turn one bundle into another, and apply does it. A BundleDelta names the bundle it applies to and the bundle it produces by their bundle_hashes. apply takes the base as the bytes the agent verified and refuses any other base, and checks that the result hashes to result_bundle_hash before it returns it, so a delta can only ever give the exact canonical bytes of the new bundle, or an error.

Operations work on the canonical body:

  • rules are added or replaced (put_rule) and removed (remove_rule) by rule ID, within their rule set;
  • a rule set whose own fields changed, or that is new, is replaced whole, without its rules (put_rule_set), and one that is gone is removed (remove_rule_set);
  • the header, the policy (without its rule sets), the libraries, the source revisions and the metadata digest are replaced whole when they changed.

The delta is itself encoded with to_bytes, canonically, so #225 can sign it with both hashes. The server sends a delta only when the agent’s bundle is its base and it is smaller than half the full bundle (worth_sending).
