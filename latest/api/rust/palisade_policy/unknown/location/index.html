Location classes from a normalised path and ACL facts (#39, #4).

The agent normally sets ObjectFacts::location_class itself, because it knows the volume, the path variables and the writable-path scanner’s results. Those classes are facts: exactly those, and no others. classify is the reference rule the agent follows, and the engine uses it, with the path’s volume fact (PathFact::volume) and the path variables of the evaluation, when the agent left the classes unset.

§Three-valued classes

A location class can relax a decision as well as tighten it: stage 6 takes the most restrictive entry among the classes an object is in, and default when it is in none with an entry. So the classifier never grants a class from a guess. For each class it answers, with the crate’s Kleene logic (Tri):

  • Match: the facts establish it;
  • NoMatch: the facts rule it out;
  • Unknown: a missing fact could make it true. The missing facts are listed (Classified::missing, MissingFact).

Stage 6 resolves the level from the Match classes, as before, and then also applies every Unknown class’s entry (or default where it has none), taking the most restrictive (crate::unknown). Removing a fact only turns a Match or NoMatch class into Unknown, which can only add to that maximum, so a missing fact never makes an object look safer (ADR 0018). With every fact present nothing is Unknown, and the classes are exactly those this classifier gave before.

What makes a class Unknown:

  • A missing path variable, for the classes it decides. Without %WINDIR%, windows and the %WINDIR%\Temp part of temp are Unknown for every path; without %PROGRAMFILES%, program_files is; without %TEMP%, temp is (unless a cache folder or the agent’s temporary folders establish it); without %USERPROFILE%, %APPDATA%, %LOCALAPPDATA% or %PUBLIC%, user_profile is (unless the path is under X:\Users\<name>). There are no drive-root guesses: a folder named \Windows, \Program Files or \Windows\Temp is not the system’s unless the variable says so. With a variable present, it decides: Match or NoMatch, never Unknown, for the folders it lists, so a %PROGRAMFILES% that lists only C:\Program Files makes C:\Program Files (x86) NoMatch.
  • An unknown volume kind, for removable, optical, network (on a drive path), and the classes that need a fixed volume: program_files, windows and other_fixed.
  • No usable path (none, or not a drive or UNC path, or an 8.3 short name the agent could not expand): every class the path decides. A known removable, optical or network volume still rules out program_files, windows and other_fixed, which no path on it can be in.
  • No ACL fact (PathFact::user_writable): user_writable_other, unless a directory the scanner flagged establishes it. A writable ACL or a flagged directory is Match, and a safe ACL is NoMatch.
  • Derived classes follow the logic: other_fixed (a drive path on a fixed volume in none of user_profile, temp, program_files and windows) is Unknown whenever one of those is.

Consequence. A missing variable can make many paths Unknown for one class, so a policy with a strict entry for that class blocks more unknown objects while the fact is missing. That fails closed, and only affects objects no rule decided. The endpoint agent is expected to supply the volume kind and every variable; the decision names what was missing (crate::unknown::UnknownHandling::missing_facts).

networka UNC path, a mapped drive (its alias is UNC), or a network volume

tempunder %TEMP% or %WINDIR%\Temp, any INetCache or Temporary Internet Files folder below the drive or share root, or a directory the agent lists as a temporary cache
user_writable_otherthe ACL facts say a non-administrator can write the file or a directory above it, or it is under a directory the scanner flagged; Unknown without the ACL fact, or when the path is not usable
program_filesunder %PROGRAMFILES%, on a fixed volume
windowsunder %WINDIR%, on a fixed volume
other_fixeda drive path on a fixed volume that is in none of user_profile, temp, program_files and windows; it can come with user_writable_other and ads

program_files and windows are the protected classes, so they are never given to a file on a removable, optical or network volume, or to a network path: a disc or share holding its own \Windows folder is not the system’s. When the path has an alias (the other spelling of a mapped drive or a UNC path), both spellings are classified and a class is the or of the two, except that a network spelling of either rules out the protected classes. Paths compare without case, at component boundaries.
