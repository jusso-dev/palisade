system_baseline: the managed, read-only rule set that lets a stock Windows install boot and log on under default-deny (#39).

It holds one allow rule. An object matches when all of these hold:

  • a trusted signature from one of the OS publishers the agent reports (SystemBaseline::publishers). The publisher names come from the agent’s view of the OS catalogs (#3, #4), not from this crate;
  • the file is under %WINDIR% or %PROGRAMFILES%. As in every allow, a path only identifies an object where no non-administrator can write it (#31), so a writable file never matches; and
  • the file is not in one of the mandatory exceptions: the known user-writable folders inside the Windows directory (MANDATORY_EXCEPTIONS, ISM-1392), every directory the writable-path scanner flagged (SystemBaseline::writable_dirs), and any alternate data stream.

The rule set is a baseline, read_only set with the well-known ID SYSTEM_BASELINE_ID. It is added to a policy only after validation (ValidatedPolicy::with_system_baseline), from facts the agent or server trusts; an authored document may not contain it. It is a floor at stage 4: the evaluator decides over its rule only when no other allow or deny matched, so under every precedence model (including first_match with curated_first) a tenant’s rule wins over it. A mandatory deny, at stage 1, still blocks anything it covers, so the baseline cannot re-enable a blocked binary (#35, ADR 0004).

Every input value is checked before the rule is built: publishers are trimmed text, and scanner-flagged directories are drive or UNC paths with no stream, so no value can be silently ignored at evaluation.

Constants§

MANDATORY_EXCEPTIONS
The user-writable folders inside the OS locations that the baseline never allows, as path wildcards (ISM-1392). %SYSTEM32% stands for both the native and the 32-bit system directories. The crypto store is written with a wildcard for the vendor folder above it.
MAX_WRITABLE_DIRS
The most scanner-flagged directories one baseline can hold: the rule’s criteria limit, less the criteria the rule always has, times the values per criterion.
SYSTEM_BASELINE_ID
The well-known ID of the managed system_baseline rule set.
SYSTEM_BASELINE_RULE_ID
The ID of its rule.

is_system_baseline
Whether set is the managed system_baseline: its well-known ID, as a read-only baseline rule set. Validation rejects SYSTEM_BASELINE_ID in every authored document (reserved_rule_set_id), so in a ValidatedPolicy only the set ValidatedPolicy::with_system_baseline added can be it.
system_baseline
The system_baseline rule set for facts, with the order and priority that make it valid under policy’s model: a catch-all order under first_match, and the weakest priority under priority. The evaluator treats it as a floor under every model anyway.
