Unknown and unhandled applications: stage 6 of the pipeline (#39).

When no rule decides, the policy’s UnknownPolicy does. Stage 6 runs only after stages 1 to 5 decided nothing, so it can never override an explicit deny or allow. The default configuration blocks every unknown object, which is the implicit deny of #35 and ADR 0004.

§Level

The level is the most restrictive of the entries that apply to the object (resolve_level): its type’s by_type entry, the by_location entry of each location class it is in, and the by_origin entry of each origin. default applies only when no entry does. The location classes come from ObjectFacts::location_class, or, when the agent did not set them, from the path (location::classify). The origins come from ObjectFacts::origin.

§Missing facts never make an object look safer

Each location class and origin is three-valued: the facts establish it (Match), rule it out (NoMatch), or a missing fact could make it true (Unknown). The level above is resolved from the Match classes and applied; then each Unknown class’s entry (or default where it has none) is applied too, and the most restrictive applied level wins, with FallbackReason::MissingFact. Removing a fact can only turn a class Unknown, so it never lowers the level (ADR 0018). The decision lists the Unknown classes and the missing facts (UnknownHandling), and the explanation names them. location says what makes a location class Unknown.

Origins: when the agent’s origin collection did not report (ObjectFacts::origin is None), the origin is unknown, and every other origin is Unknown, so the strictest matching by_origin entry applies. Under the default preexisting_policy: baseline_only, the preexisting origin then blocks: an agent that sends no origin facts gets every unknown object blocked in enforce mode (in audit, monitor and learning it shows as would-block), and missing_facts names origin. A reported set is complete; an empty one means no evidence was found, which is exactly {unknown}.

Every stage-6 decision is unhandled (Decision::unhandled) and carries an UnknownHandling that says which entries applied and why a fallback was taken. The policy’s unknown.effects apply to every level. A field left unset takes the level’s default: block and prompt take a deny’s defaults, except that prompt shows no notification (the prompt is the notification). restrict and detect log every decision at once with severity medium. allow takes an allow’s defaults, so it is silent.

§Fallbacks, all closed

Some levels cannot apply. Each case is recorded in UnknownHandling::fallback:

  • prompt is never offered for an object that a blocklist rule matched (a deny, or any rule of a blocklist rule set, including one that a non-enforcing mode set aside), for a library or a driver, or when the session has no interactive user (SessionContext: only console and rdp sessions of a user who is not the system account are interactive). Those use the prompt’s fallback.
  • restrict needs the containment component (DeviceContext::containment_available). If it is not known to be installed, or the object’s type cannot be contained, the object is blocked with restrict_unavailable.
  • With preexisting_policy: baseline_only (the default), an object whose origin is preexisting is blocked: only the approved baseline, whose rules decide at stage 4, lets it run.

§Modes

Stage 6 decides as enforce mode sees it. Evaluator::evaluate_in relaxes a blocked or pending_user result in a mode that does not enforce, as it relaxes the implicit deny (#36): no prompt is shown in audit, monitor or learning. In learning, every object stage 6 decides is a learning candidate, whatever its level. An object that a deny rule would block never is.

A driver loaded during early boot (BootPhase::Early) follows driver_boot_policy: with audit, the default, stage 6 only reports what it would block. Explicit rules still apply.

§Palisade’s own images

Evaluator::with_self_images pins the agent’s own binaries by hash and signer. A pinned image is allowed right after stage 1, whatever the tenant’s ordinary rules say. The mandatory tier still runs first (ADR 0004), so PolicyDocument::validate_with_self_images rejects every deny that could match one (selfpin).
