The lenient reader: policy documents of a newer minor version (#30, #330).

A minor version only adds optional fields. A reader built for an older minor does not know them. PolicyDocument::from_json (strict mode, the default and the only mode for authoring) rejects them. read_json reads the document anyway, but only where that cannot relax a decision (ADR 0018). An unknown field has no known meaning, so the reader cannot tell whether it would have restricted something. It therefore only skips what never decides:

  • Governance data. A field of a metadata object (the policy’s, a rule set’s or a rule’s), or of the policy’s governance settings, that is unknown or whose value cannot be read is set aside. Metadata never changes a decision (PolicyDocument::decision_relevant), and governance settings only steer review and publishing.
  • Rules that never let an object run. A rule that cannot be read, for example because its match tree tests a criterion this reader does not know, is unreadable. If its action is audit, defer, trust_source or ignore, the rule is set aside. Without it, nothing that was blocked can run: an annotation or a trust grant is lost, or an excluded object is decided by the policy instead.

Every other unreadable part refuses the whole document (LenientError), and the device keeps the policy it has (ADR 0018, “new bundle fails verification or activation”). That covers an unknown field anywhere else, and an unreadable rule that allows, denies, or has an action this reader does not know. The reader cannot drop such a rule without risking a relaxation: without a deny, the object may run. Without an allow_contained, a plain allow may win in its place. Without a plain allow, an allow_elevated may.

What is set aside is kept, with its JSON Pointer and value, in Lenient::ignored, so a caller can report it.

Documents of an older major version are migrated first (crate::migrate).
