Module context 

Source
Expand description

The context of one evaluation: the user, device and session (#33).

Context criteria (user.*, device.*, session.*) test these facts. As with ObjectFacts, this module only defines their shape: the agent collects them (#4), and evaluation never reads the system. A fact that was not collected is None, and every criterion on it evaluates to Tri::Unknown.

Every fact here is plain data, already known when a decision starts, and the caller supplies all of it: EvaluationContext::new knows nothing, so every context criterion is unknown until the caller fills the facts in. Collecting them on the endpoint is #4. The caller (the agent) collects the network facts on network changes and heartbeats, and converts the time facts from its trusted clock (#18) into the clock the policy’s time_zone_basis names; nothing here reads the host clock. When the clock cannot be trusted it leaves the time facts out, so every time criterion is unknown: an allow that depends on the time fails closed. Facts that cost a lookup at decision time (registry, files, environment blocks), their cost classes and caching are later parts of #33. The facts only scopes read (ScopeFacts) are part of rule scoping (#38).

normalize_sid
The canonical form of a SID (MS-DTYP 2.4.2.1): S-1-, the identifier authority, then 1 to 15 decimal sub-authorities without leading zeros. The authority is written in decimal when it is below 2^32, and otherwise as 0x and 12 lowercase hex digits, as Windows writes it. On input it may be written either way, in any case, and decimal numbers may have leading zeros. The result is itself canonical: normalising it again gives the same text. None if s is not a SID.
