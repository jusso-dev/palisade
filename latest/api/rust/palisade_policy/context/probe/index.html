Probed context: environment variables, the registry and the file system (#33, #329).

env.var, reg.key, reg.value, fs.file and fs.folder criteria name a target to look at. The agent collects what the policy’s criteria name (probe_targets) into a Probes table before the decision: evaluation never reads the system. Every lookup is keyed by the canonical target (canonical_target), so the agent and the evaluator agree on what one target is.

A target the agent did not look at is absent from the table, and every criterion on it is Unknown, negations included. A target it looked at and found missing is Probe::Absent: then exists is NoMatch, not_exists is Match, and every comparison is NoMatch (there is nothing to compare), so not_equals on an absent value is Match.

§User-controlled context

A user sets their own environment, writes their own registry hives (HKCU, HKU, and HKCR, which merges the user’s classes over the machine’s) and creates or deletes files wherever they can write. A policy cannot see which locations those are, so every env.* and fs.* criterion, and every reg.* criterion outside the machine hive, is user-controlled (is_user_controlled). Validation keeps such a criterion from being the reason an allow matches (user_controlled_context), and the decision trace marks every rule that read one.
