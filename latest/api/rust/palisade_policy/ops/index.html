Matching one criterion against the facts about one object (#31, #32).

A Criterion is compiled once, when the policy is loaded, into a CompiledCriterion: regular expressions and wildcards become automata, and literal values are normalised and case-folded. Matching then does no compilation and runs in time linear in the fact’s length.

§Three-valued results

Every evaluation gives a Tri: Match, NoMatch, or Unknown when a fact the criterion needs is missing or cannot be trusted. A negative operator is the Kleene negation of its positive form, so a negated test of an unknown fact is Unknown, never Match: “does not contain X” is not satisfied by a value nobody computed. A whole tree combines these results with the same logic, and a rule only matches on Match (crate::condition), so Unknown never allows.

§Several values

A positive operator matches if any value matches. A negative operator matches if no value matches: not_contains [a, b] means the fact contains neither a nor b.

§Comparing text

Strings are compared after Unicode NFC normalisation, so composed and decomposed spellings of one name are equal. Unless the criterion sets case_sensitive: true, both sides are then folded with the Unicode simple upper-case mapping: one character to one character, with no locale rules, so the result does not depend on the machine’s language. This is how NTFS compares names: i, I and the dotless ı are equal everywhere, and the dotted capital İ is distinct from all three. A character whose upper case is several characters, such as ß, is left as it is. Hash values are compared as hex digits in either case.

§Paths

Path facts and path values pass through the same lexical normalisation ([palisade_core::path]). A path criterion evaluates to Unknown when the path is missing, is not a drive or UNC path, or contains a short (8.3) name the agent could not expand. A mapped network drive matches in both its drive form and its UNC form (PathFact::alias).

On path.full and path.directory:

  • starts_with ends at a component boundary: C:\Tools matches C:\Tools\a.exe but not C:\ToolsX\a.exe.
  • A value may start with a path variable, such as %PROGRAMFILES%\App, for equals, starts_with and wildcard and their negations. The variable is expanded for this evaluation (PathVariables); a variable with no value makes the criterion Unknown.
  • In wildcards, * matches any run of characters within one component (as a whole component it needs at least one character, so C:\* does not match the bare root C:\), ? exactly one character other than \, and ** any run of characters across components. As a whole component (\**\, a trailing \** or a leading **\), ** matches zero or more whole components, so C:\a\** matches C:\a itself and everything below it, and C:\a\**\b.exe matches C:\a\b.exe. [*] and [?] match a literal * or ?. A value written with / is read with \.
  • An alternate data stream is its own object. On path.full, a value that does not name a stream never matches one, and a value that names a stream only matches streams: C:\x\* does not match C:\x\a.txt:payload, C:\x\*:* does, and **:** matches no plain file. A value names a stream when its last component has a : that is not a drive letter’s. match_ads: true, on a positive test of path.full, lets a value that names no stream also match the streams of a file it matches; a negative test cannot take it, so a stream never escapes a rule written for its file. A regular expression is never tested against a stream’s own name, so by default it never matches a stream; with match_ads: true it is tested against the file that holds the stream, and matches the stream if it matches that file. path.directory, path.file_name and path.extension describe the file that holds the stream.

On every other string field, * and ** match any run of characters, and ? matches one.

Path identity is only trusted where users cannot write. In a rule that lets an object run, trusts it or excludes it (an allow, and the other actions with ActionKind::needs_identity, #34), a positive path.* test that would match evaluates to Unknown, with the note Note::PathAclUnsafe, unless the facts show that no non-administrative principal can write the file or a directory above it. Unknown rather than NoMatch, so that the test also fails closed under negation.

§Regular expressions

regex and not_regex use a linear-time engine with RE2 semantics (a lazy DFA with a PikeVM fallback; no backtracking). Patterns are anchored at both ends and are case-insensitive unless case_sensitive: true. Case-insensitive matching uses the engine’s Unicode simple case folding, which differs from the folding above for a few characters (the dotless ı does not match i or I). On path fields the fact is the normalised path, so write \\ for each separator. These constructs are not supported and are rejected when the policy is validated:

  • look-around: (?=…), (?!…), (?<=…), (?<!…). Write the negative part as a second criterion with not_regex, in an all with the first.
  • backreferences: \1, \k<name>.
  • patterns whose compiled form exceeds REGEX_SIZE_LIMIT.

Path variables are not expanded inside regular expressions.

anchored: false lets a pattern match anywhere in the fact instead of the whole fact (Suite [0-9]+ then matches Example Suite 12 (x64)). Only regex and not_regex take it.

§Versions

A version is up to four dot-separated numbers, each at most 65535, with missing parts read as zero: 10.0 equals 10.0.0.0. Facts may also separate the numbers with commas (10, 0, 19041, 1). A fact with a non-numeric suffix (10.0.19041.1 (release)) is compared without it, with the note Note::VersionSuffixStripped. A fact that is not a version at all is Unknown, with Note::VersionUnparseable, so it never satisfies a version test in either direction. The bounds mean the same in allow and deny rules: version_between [min, max] includes both. On version fields, equals and not_equals compare versions too.

§Signers

A signer criterion looks at every signature on the object and matches if any of them matches. By default only signatures whose status is valid, valid with an expired but timestamped certificate, or catalog-signed take part: a revoked, untrusted, expired or digest-mismatched signature never vouches for an object, and an unsigned object matches no signer. The criterion’s signer options choose other statuses, a source and an index, and add constraints on the same signature; see signer.

§Context

Context criteria (#33) test the user, device and session in EvalContext::context rather than the object. They follow the same rules: a fact that was not collected is Unknown, and so is its negation.

  • SIDs (user.sid, user.primary_group) are compared in canonical form: s-1-5-32-544 equals S-1-5-32-544, and leading zeros are ignored. A SID fact that is not a SID is Unknown, with Note::FactMalformed.
  • Sets (user.groups, device.groups, device.tags) take member_of and not_member_of: member_of matches if the set holds any value, not_member_of if it holds none. Group members are SIDs or cloud-directory object IDs (GUIDs, in any case); a member of the fact that is neither is unknown, with Note::FactMalformed, so it never lets not_member_of match. Tags are text, and case-insensitive unless case_sensitive: true.
  • user.name is tested against both the account name (DOMAIN\user) and the user principal name, and matches if either does. A form that was not collected counts as Unknown, so a negative test only matches when both forms are known. Regular expressions are not allowed on it (#32); match principals by SID where you can.
  • Yes-or-no facts take is_true and is_false, with no values.
  • session.type takes equals and not_equals with the names console, rdp, remote_shell, service, batch and network.
  • The other device and session facts are text or versions, compared as above.

§Numbers, levels and dates

eq, ne, gt, ge, lt, le and between compare whole numbers (device.os_build, session.id), integrity levels (user.integrity_level, ordered untrusted < low < medium < medium_plus < high < system < protected) and dates (time.date, YYYY-MM-DD, which also takes date_between). between and date_between take a minimum and a maximum and include both. Numbers are decimal with no sign, at most 2^64 - 1.

§Addresses

session.client_ip is one address and net.ip the set of local addresses; a test of the set matches if any address matches. ip_in_cidr takes CIDR blocks (10.0.0.0/8, 2001:db8::/32, whose address must be the first of the block), ip_between takes ranges (192.168.1.10-192.168.1.20, or 192.168.1.10-20), and ip_wildcard takes IPv4 octet patterns (10.*.*.*). equals compares addresses, and the set operators test members of net.ip. An IPv4 address written in IPv6 form (::ffff:10.0.0.1) is the IPv4 address. net parses all of these, and scopes (#38) use it too. net.mac holds MAC addresses (aa:bb:cc:01:02:03, AA-BB-CC-01-02-03 or aabbcc010203).

§Sets

member_of and any_of match if the set holds any value, all_of if it holds every value, and not_member_of if it holds none. A member of a principal set that is neither a SID nor an object ID makes a value it might be unknown, so it never lets not_member_of match or all_of fail. net.ip is a set of addresses: a set test (member_of, any_of, all_of, not_member_of) compares the listed addresses with it, so all_of needs every one present, while a network test (ip_in_cidr, ip_between, ip_wildcard) matches if any local address does. net.dns_suffix and net.location are sets of names, compared like tags.

§Directory units

user.ou and device.ou read the distinguished name of the user’s or device’s directory object and test the unit it is in: the name without its first component. Names are compared component by component, without case or spaces around = and ,, after decoding the escapes of RFC 4514 (\, and \2C are the same comma). A name with an escape RFC 4514 does not define cannot be compared: as a rule value it is invalid, and as a fact it is unknown. include_sub_ous: true also matches units below the named one.

§Time

The agent supplies the weekday, time of day and date in the clock the policy’s time_zone_basis names, from its trusted clock, and leaves them out when the clock cannot be trusted, so every time test is then unknown and an allow that depends on the time fails closed (#18). weekday_in takes mon to sun. time_between [start, end] (HH:MM) includes the start and excludes the end, and wraps midnight when the end is before the start (22:00, 06:00); an empty window is rejected.

§Failing closed in mandatory blocklists

A criterion in a mandatory blocklist may be safety_critical: true. When it is unknown, it counts towards the deny applying, so a shipped blocklist blocks an object whose facts are missing instead of letting it through (crate::condition::CompiledMatch::eval_mandatory, #87). Validation rejects the option anywhere else.
