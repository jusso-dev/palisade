Signer criteria (#31): which signatures take part, and how each is tested.

A signer criterion matches if any signature that takes part satisfies both its field test and every constraint of its options. A signature takes part when:

  • its status is accepted: by default valid, valid_expired_timestamped or catalog_signed, or the rule’s accept_status. A digest_mismatch signature takes part only with allow_digest_mismatch: true, which validation always warns about;
  • it comes from the chosen source (embedded, catalog or any);
  • it is at the chosen signature_index, counted among the signatures of that source, if one is set.

The constraints (signed_after, countersigned, min_key_bits, disallowed_algorithms) are combined with the field test with Kleene AND, per signature. A fact a test or constraint needs that is absent or malformed makes that signature’s result Unknown (Note::FactMissing, Note::FactMalformed), so it can never be what makes a criterion match, and a negated signer test on it is Unknown too.

  • signer.publisher compares the leaf subject’s common name, or with component its organisation (o) or whole distinguished name (full_dn).
  • signer.tbs_hash compares the TBS hash of the leaf, the intermediates, the root, or any of them (position, default any). Digests are 40, 64, 96 or 128 hex digits, compared in either case.
  • signer.spki_sha256 compares the SHA-256 of a certificate’s public key at the same positions (#318). The TBS hash names one certificate; the key hash names every certificate issued for the key.
  • signer.eku holds the leaf’s extended key usages as a set of OIDs, compared arc by arc, so 1.3.6.01 equals 1.3.6.1.
  • signed_after needs a trusted timestamp at or after the instant; the signer’s own claimed signing time is never used. Timestamps are whole seconds, so a fractional instant is rounded up.
  • min_key_bits needs every key of the chain to be at least that strong, in RSA-equivalent bits (KeyFact::rsa_equivalent_bits).
