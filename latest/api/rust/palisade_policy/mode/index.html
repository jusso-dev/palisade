Module mode

Expand description

Enforcement modes: which mode applies to one decision, and what it does to the decision (#36).

The evaluator (crate::evaluate) first computes the enforce-mode decision. resolve then finds the effective mode for that decision, and Evaluator::evaluate_in applies it. Everything here is a pure function of the policy and a DeviceState that the agent supplies; nothing reads a clock. The state machine that changes a device’s mode over time is in machine, and which decisions each mode reports is in events.

§The modes

ModeEffect on a decision
disabledThe engine is not consulted: there is no decision (Evaluator::evaluate_in returns None). Mandatory denies do not apply, and the device is reported disabled. Only a whole device can be disabled.
monitorEvaluated fully. What enforce mode would block runs (allowed_audit), and would_have_been is blocked.
auditAs monitor. The two differ only in which decisions are reported (events).
learningAs audit. An object that only the implicit deny would block is also a learning candidate (Decision::learning_candidate).
enforceDecisions take effect.

Two kinds of block are never relaxed by a mode, a session or any override, only by disabled:

  • A mandatory deny (ADR 0004, #125: the blocklist always wins). It blocks in monitor, audit and learning, during every override session including full_bypass, and whatever a rule set’s mode_override says (validation rejects one on a mandatory rule set).
  • An always_enforce rule, except during a full_bypass session.

§Resolution

For an object of type t decided by rule (or by the implicit deny), in this order:

  1. Lockdown. If DeviceState::lockdown is set, enforce, and stop. Sessions, a disabled device mode, type modes, control levels, rule set overrides and never_enforce are all ignored.
  2. Device mode. The device’s base mode, DeviceState::mode (the policy’s mode, or what the machine moved it to). disabled stops here: no decision.
  3. Mandatory deny. If rule is in a mandatory rule set, enforce, and stop.
  4. Disconnected. While the device is disconnected, a mode_disconnected stricter than the device mode replaces it.
  5. Object type. mode_by_type[t] if set (raised to a stricter mode_disconnected while disconnected), otherwise the device mode. Then the class’s control level in the settings (script_control, script_control_by_kind, dll_control, driver_control) caps it: audit caps it at audit, and off caps it at monitor. off means the agent does not intercept the class (#4, #92); if such an object is evaluated anyway, only a mandatory deny, a blocklist with mode_override: enforce or an always_enforce deny blocks it.
  6. Rule set. The mode_override of rule’s rule set, if set, replaces the mode. Only non-mandatory blocklists may have one.
  7. Rule. For a deny, always_enforce makes it enforce and never_enforce caps it at audit. Other actions cannot set it.
  8. Override session (#9). An active session caps the mode at audit, unless the rule is always_enforce and the session is not full_bypass.

A cap lowers a mode to the cap’s strictness and never raises it. Strictness ranks enforce above learning and audit (equal), above monitor, above disabled (strictness).

Lockdown never changes DeviceState::mode, so clearing it restores every prior mode.
