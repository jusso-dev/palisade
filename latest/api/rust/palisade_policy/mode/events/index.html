Event fidelity per mode (#36): which decisions a mode reports, and how.

The engine classifies; the agent emits the events, and their wire format is #16. fidelity maps one result of Evaluator::evaluate_in to a Report, from the decision’s effective mode, its outcome and its effective log flag:

Decisionenforcemonitoraudit, learning
none (device disabled)–––
ignorednonenonenone
blockedthe rule’s logthe rule’s logthe rule’s log
would-block (allowed_audit)–eventevent
allowed_overrideeventeventevent
allowedthe rule’s logsummaryevent
  • A disabled device makes no decisions and reports none; the agent only sends its periodic heartbeat, which says the device is disabled (#4).
  • monitor is the low-volume mode: a full event for each would-block, and allowed objects only in the periodic summaries (or not at all where the rule says log: never).
  • audit and learning are full fidelity: every decision is an event, whatever its rule’s log says. Only ignore stays silent.
  • A learning decision that is a learning candidate (Decision::learning_candidate) is an event with the object’s full facts, for the recommendation pipeline (#5).
  • A block keeps its rule’s log, which validation only allows to be always or sampled on a deny, so every block is loggable. The implicit deny logs always.
  • The use of an override session is always an event (#9).

A relaxed or overridden block keeps the deciding rule’s effects, so the event’s severity, tags and upload timing are the rule’s.
