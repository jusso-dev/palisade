The mode state machine: which mode changes are legal, and when a time-boxed mode ends (#36).

A ModeMachine holds a device’s base mode (DeviceState::mode) and, when the device was moved to a weaker mode for a limited time, the TimeBox that moves it back. It is pure: every call takes the time from the caller (Now, usually from a Clock), and the agent stores the machine between calls (#69).

§Legal transitions

FromTo
disabledany
monitoraudit, learning, enforce, disabled

enforceaudit, learning, monitor, disabled, each time-boxed

A mode never transitions to itself. Every other change is rejected (TransitionError::Illegal), and a rejected request changes nothing.

§Time boxes

Leaving enforce for a weaker mode, and entering disabled from any mode, needs a reason, a ticket reference when the tenant requires one, and an expires_at at most 30 days ahead. Only enforce to audit may instead be permanent, and only for an actor with the elevated permission (Governance::may_weaken_permanently).

When a time box ends, the machine moves back to the mode it left (its rollback target, TimeBox::prior), with no server involved, so an offline device reverts too. A later change to a mode at least as strict as the target ends the box early. Any other change keeps it: the device still reverts to the target at the same time, and the change cannot set an expiry of its own. A change inside a box to a mode weaker than the target still needs a reason (and a ticket where required).

A time box is a target for clock rollback: setting the clock back would keep a weaker mode alive. So the end is checked against two clocks, and the first to pass ends the box (ADR 0012):

  • the wall clock reaches expires_at; or
  • the monotonic clock has advanced by the box’s budget (expires_at minus the wall time when the box started), whatever the wall clock says.

Setting the wall clock back therefore cannot extend a box, and setting it forward only ends one early, which is the strict direction. A monotonic reading below the box’s start (the agent restarted, and its monotonic clock with it) also ends the box. Carrying the remaining budget across a restart in protected storage, as ADR 0012 does for override sessions, is the agent’s part (#69, #220).

§Readiness gate

A requested move to enforce can be gated on readiness (#41): the caller runs readiness over the recent events, and when its gate says a readiness_ack is required (ReadinessGate::ack_required), sets Governance::readiness_ack_required. The request must then carry Request::readiness_ack, or it is rejected (TransitionError::ReadinessAckRequired). The gate never applies to a change that only returns a device to enforce from a time box that left it, nor to the revert when a box ends: restoring enforcement is never held back.

Every change, requested or by expiry, gives a ModeChanged record for the mode_changed event (#16).
