Which facts an evaluation needs: the lazy fact demand protocol (#42).

Facts cost very different amounts to compute. The path, the process, the user and the file ID are known when an event arrives. A hash needs the whole file read, a signature needs a chain built, and an ACL check needs every directory above the file examined. The engine therefore never asks for an expensive fact unless a rule that could still decide needs it.

A FactSet names classes of facts. The agent says which classes it has computed (FactSet::CHEAP is always taken as computed), and the engine either decides or answers NeedFacts with the classes it needs next (crate::engine::Engine::evaluate). It asks for them in a fixed order, one round at a time (FactSet::ROUNDS):

  1. the hashes (FactSet::HASHES),
  2. the signatures and the version resource (FactSet::SIGNERS, FactSet::METADATA),
  3. the path ACL (FactSet::PATH_ACL).

So a decision takes at most three extra rounds. Within a computed class, a fact that is absent is unknown, as always (crate::facts).
