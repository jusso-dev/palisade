The policy assistant: static analysis of a policy (#40).

analyse runs on every save, on bundle compile (publish_gate) and on demand (the CLI’s pal policy lint, #15). Each Finding has a stable FindingCode, a severity, the rules it is about, a message and an optional suggested fix. Findings are sorted, so the output is a deterministic function of the policy, the facts and the time.

A policy can raise a finding’s severity (policy.governance.severity), never lower it below the code’s default: validation rejects that, and the assistant reports the higher of the two. error findings block publishing unless a tenant administrator overrides them with a reason (publish_gate).

§Conflicts

shadowed, contradiction and ineffective_vs_mandatory need a proof that one rule matches whenever another does (subsume::covers). The proof is conservative: a finding is only made when it is certain, so a rule reported as shadowed or ineffective truly never decides (a property test checks this against the evaluator). Rules are compared only when they share an identity value (an exact hash, publisher or path), which keeps the analysis near linear on large policies.

  • ineffective_vs_mandatory: an allow that a mandatory deny always blocks first (stage 1).
  • shadowed: a rule that another rule of the same verdict always outranks, under the policy’s model, so it never decides. Only proven for deny_wins among denies and for first_match, where the outcome order is fixed. Other cases are left to the decision trace (#41).
  • contradiction: an allow and a deny where one covers the other, so for some objects both match, and the precedence model alone decides. Under deny_wins, an allow covered by a deny never decides, which is reported as shadowed instead.

Modules§

identity
What a rule’s tree guarantees about the object, for the policy assistant (#40). Conservative in the same way as validation (#31): all guarantees the strongest of its children, any only the weakest, and not nothing.
subsume
A conservative proof that one match tree matches whenever another does (#40): covers(a, b) is true only if every object and context for which b is Match also makes a Match. It never claims more, so a rule the policy assistant calls shadowed or ineffective truly never decides. It does not find every such pair: an unproven pair is just not reported.
