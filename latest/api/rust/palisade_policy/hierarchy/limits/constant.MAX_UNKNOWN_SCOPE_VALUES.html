Most scope values in one effective policy’s unknown-application limits (unknown.scope_limits, #39): over every contributing policy, its scope and its unknown.scopes.

Chosen by measurement, on a release build, of building one effective policy and serialising it (about 77 bytes per scope value):

Scope valuesBuildSerialised
10,00019 ms772 KiB
20,00038 ms1.5 MiB
50,000101 ms3.9 MiB

The build is linear and fast; the size is what limits it, because each agent receives its effective policy. Snapshot validation rejects a hierarchy in which any device could exceed this (too_many at /nodes/<n>/assignments), so an effective policy built from a valid snapshot never does. The check uses an upper bound: a node’s own layers plus every dynamic group of its tenant, because which dynamic groups a device is in is only known when its policy is computed. It is pessimistic for tenants with many dynamic-group policies by design.
