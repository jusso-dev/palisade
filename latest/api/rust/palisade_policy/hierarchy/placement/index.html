Module placement 

Source
Expand description

Automatic placement: which group a device belongs in (#37).

Each tenant has an ordered list of placement rules. The first rule whose conditions all match places the device in its target group. Every list ends with an implicit catch-all that places every other device in the tenant’s built-in unassigned group, so the catch-all cannot be deleted or reordered. A rule may target only an ordinary group of the same tenant that has not opted out (allow_auto_assignment: false); staging, unmanaged and unassigned cannot be targets (unassigned is reached through the catch-all).

A device whose current group has opted out is never moved (PlacementOutcome::Kept). Placement runs on first contact and on every reconnect, and on a change of signed-in user only if the tenant sets place_on_user_change (PlacementTrigger).

§Conditions

Each set condition must match; within one condition, any value may. Text is compared without case.

  • directory_ou: the device’s directory OU equals the value or is below it (OU=Laptops,DC=example,DC=org includes OU=Sales,OU=Laptops,DC=example,DC=org).
  • directory_groups: the device is in one of the groups (SIDs or object IDs, canonical form).
  • hostname: a wildcard with * (any run of characters) and ? (one).
  • networks: the device’s IP address is in one of the CIDRs (IPv4 or IPv6).
  • tags: the device has every tag.
  • os: the device’s OS name starts with one of the values.

A fact the device did not report never matches, so an unknown device falls through to unassigned.
