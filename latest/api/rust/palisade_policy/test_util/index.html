Builders for tests: policies, rule sets, rules, match trees, object facts and evaluation contexts (#25).

Only compiled with the test-util feature, which only [dev-dependencies] turn on (cargo xtask check-manifests enforces it), so none of this reaches a release build. Other crates’ tests use it with

[dev-dependencies]
palisade-policy = { workspace = true, features = ["test-util"] }

Every builder starts from the smallest valid value and changes only what the test sets, so a test states what matters to it and nothing else. IDs are deterministic: the same calls give the same document, so snapshots of it are stable.

use palisade_policy::model::ObjectType;
use palisade_policy::test_util::{PolicyBuilder, RuleBuilder, RuleSetBuilder, facts, hash, subject};

let policy = PolicyBuilder::new()
    .rule_set(RuleSetBuilder::allowlist(1).rule(RuleBuilder::allow(1, hash('a'))))
    .validate();
let facts = facts().sha256('a');
let decision = subject(&facts).object_type(ObjectType::Executable).decide(&policy);
assert_eq!(decision.outcome(), palisade_policy::decision::Outcome::Allowed);
