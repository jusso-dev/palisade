Module migrate 

Source
Expand description

Migrations between major versions of the policy schema (#30, #330).

A minor version only adds optional fields, so any reader of a major reads every minor of it (SchemaVersion::is_readable_by). A major version is a breaking change, and a document written for an older major is brought up to crate::schema::CURRENT by migrations.

Each Step migrates a document from one major version to the next: migrate(vN) -> vN+1. Steps are pure functions from a JSON object to a JSON object; they read no clock, file or setting, so a document always migrates to the same result. migrate applies every step from the document’s major to the current one, in order, and returns a document of the current major unchanged, so migrating twice gives the same result as migrating once.

A migration only rewrites the shape of a document. It never decides what an unknown field means: a field the steps do not know is left in place, and the strict reader then rejects the migrated document, as it rejects any other document with an unknown field. A migrated document is therefore never more permissive than its author wrote (ADR 0018).

§Versions

  • v0 (0.y.z) is the draft model of #30, from before the first release. It differs from v1 in two ways, which v0_to_v1 rewrites:
    • schema_version is a field of policy, not of the document;
    • a rule’s effect flags are called flags; v1 calls them effects, with the same fields.
  • v1 is the current version, described by schemas/policy/v1.json.

§Reading

read_json reads a document of any supported major version: it reads the JSON, rejecting repeated object keys as the strict reader does, migrates it, and then reads the result with the strict model. Use PolicyDocument::from_json where only the current major is acceptable.

§Tests

tests/fixtures/migrate/v{N}/ holds documents written for major N. For every document in v{N}/, the step from N gives the document of the same name in v{N+1}/, and migrate gives the one in the current version’s directory, which the strict reader accepts and which validates. tests/fixtures/migrate/rejected/ holds documents that read_json refuses, with the error each one gives.
