palisade_policy::evaluate

Module index 

Source
Expand description

Candidate indexes, so evaluation is not linear in the number of rules (#42).

When an Evaluator is built, each rule is filed under the keys of its anchor (crate::ops defines the anchor of one criterion): a set of keys such that, whenever the rule’s match tree is Match, the object’s facts contain at least one of them. The anchor of a tree is:

  • a criterion: its own anchor, if it has one;
  • all: the anchor of one anchored child, since every child must match: the one on the cheapest facts (the path and the context come before hashes, then signers and the version resource), then the most selective (hashes, the leaf thumbprint, the publisher, other text, principals, path prefixes);
  • any: the union of its children’s anchors, if every child has one;
  • not: none.

The indexes, one map per field:

  • hash: decoded digest to rules, per hash field. A rule whose criterion lists 25 digests is filed 25 times, so one probe replaces scanning every hash rule.
  • signer: leaf thumbprint, the leaf certificate’s TBS hash (signer.tbs_hash at position: leaf only; a CA’s TBS hash covers every file it signed, so it is evaluated always), and the folded publisher and issuer.
  • meta: folded version-resource strings, file name and extension.
  • path: folded literal path prefixes of path.full and path.directory, cut at a separator, with values that start with a path variable filed under the variable. Wildcards are filed under their literal part before the first wildcard character, so C:\Program Files\*\x.exe is under C:\PROGRAM FILES. A probe looks up every prefix of the folded fact that ends at a separator.
  • principal: canonical SIDs and object IDs of user.sid, user.primary_group, user.groups and device.groups.
  • always: rules with no anchor, every deny with unknown_as: match, which applies when its tree is Unknown and so cannot be skipped on a probe that finds nothing, and every rule with a safety_critical criterion, which counts as matching when its fact is unknown (#32). Each is evaluated for every object of its types. Validation warns when a policy has more than ALWAYS_EVAL_WARN of them (unindexed_rules).

Mandatory denies have their own set of indexes, probed first.

Candidate selection is the union of the probes, then the full match tree is evaluated for each candidate only. A rule that is not a candidate cannot be Match, and is not an always-evaluated deny, so it does not apply: the matching rules are exactly those that a linear scan finds, and the decision is the same (a property test checks this against the linear scan, with the same decision and deciding rule).

§Lazy facts

Evaluator::evaluate_with takes the classes of facts that have been computed (FactSet). Probing reads only facts that are there, and never asks for any. Then:

  • If a rule of the object’s type is anchored on a class that has not been computed, it could still match, unless the facts computed so far already make its tree NoMatch (only checked for rules that read classes besides their anchor’s). Then that class is needed, with the classes it reads in that round or an earlier one. Its later rounds are asked for once it is a candidate whose tree is still Unknown.
  • A candidate whose tree is Unknown needs the classes it reads that have not been computed. A tree that is Match or NoMatch is settled: Kleene logic is monotone, so more facts never change it.

If anything is needed, the evaluator answers NeedFacts with the needed classes of the earliest round (FactSet::ROUNDS). Every class it asks for is read by a candidate. A rule only becomes a candidate later if it was anchored on a class that was missing, and then its classes were already needed; a settled tree stays settled. So every class of a round is asked for the first time that round is reached, and a decision takes at most three rounds after the cheap facts. If no rule could match given the cheap facts, the decision is made without asking for anything.
