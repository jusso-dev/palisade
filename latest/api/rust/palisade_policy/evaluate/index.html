The evaluation pipeline: from one object to one Decision (#35, ADR 0004).

An Evaluator is built once from a ValidatedPolicy. It compiles the match tree of every enabled rule in the rule sets the policy references. Evaluator::evaluate then evaluates every rule that applies to the object’s type and runs the stages below, in this fixed order, whatever the precedence model. Each stage either decides or passes to the next.

  1. Mandatory deny. Rules in a mandatory blocklist. If one matches, the object is blocked (mandatory_deny). No allow, trust source, elevation or exclusion can change that, under any model.
  2. Exclusion. ignore rules. If one matches, the object is ignored.
  3. Override session. An active session (#9) lowers the effective mode of stages 4 and 6 (crate::mode). It never affects stage 1.
  4. Policy. The policy’s precedence model (crate::precedence) chooses among the matching allow, allow_contained, allow_elevated and deny rules.
  5. Attribute. Not yet: post-allow attribute rules are #33.
  6. Unknown. If nothing decided, the policy’s unknown-application policy decides (crate::unknown, #39). Its default blocks (implicit_deny_unknown), the implicit deny of ADR 0004.

Between stages 1 and 2, an object that is one of Palisade’s own pinned images (Evaluator::with_self_images) is allowed (self_allow).

§Scopes

A rule is a candidate only if it is in scope (#38, crate::scope): its own scope, the scopes of its rule set’s assignment and the policy’s scope are evaluated first, and a rule applies when the AND of those scopes and its match tree is Match (or Unknown, for a deny with unknown_as: match). A rule that is out of scope behaves as if it were absent in every stage: it never decides and is not listed as overridden. The scope notes of every rule whose tree was not NoMatch (in scope or not) are in Decision::scope_notes.

Two scope settings act on the deciding rule:

  • Instance limit. If an allow that decides has a scope with max_instances_per_session and the session already runs that many instances (or the count is unknown), the object is blocked with instance_limit, naming the allow. A mode that relaxes the block runs the object with the allow’s directives.
  • Window close. If the object is allowed and a scope on the way to the deciding rule has a schedule with on_window_close, the decision carries a WindowClose directive with the instant the schedule closes.

Two kinds of rule never decide:

  • audit rules that match are listed in Decision::annotations, whichever stage decides.
  • trust_source rules that match add their grant to Directives::trust_sources, but only when the object is allowed. A trust source never lets an object run by itself (#114). When the object is blocked or ignored, they are listed as overridden instead.

§Rule lifecycle

A rule outside its activity window (activates_at, expires_at, #40) behaves as absent, exactly like a disabled rule (crate::lifecycle::activity). Evaluator::at sets the clock. Without one, or while the agent is offline-started (the clock is not anchored, ADR 0018), a time-bounded rule that lets an object run, trusts it or excludes it is inactive; without one, any other is active. An expired rule with on_expire: convert_to_audit only annotates.

defer rules have no opinion. They are never evaluated, so a defer that matches makes first_match continue with the next rule.

When several mandatory denies match, or several exclusions, the one with the most specific identity decides, then the one with the lowest rule ID.

§Overridden rules

Decision::overridden lists every other rule that matched and would have decided, or attached a grant, if the deciding rule had not: the other candidates of the deciding stage (including those with the same outcome), every candidate of the later stages, and every trust_source rule when the object is not allowed.

§Unknown facts

A rule applies only when its match tree is Match (crate::condition), so an unknown fact never allows, trusts or excludes. A deny rule decides how it treats an unknown result with two options:

  • unknown_as: match makes it apply when its tree is Unknown, so it blocks unless the precedence model prefers an allow. The default, no_match, means an unknown fact does not block.
  • on_unparseable: match makes each criterion whose version fact is not a version count towards the deny applying (Unparseable::FavourMatch). The default leaves it Unknown.

A file the agent could not parse has no facts, so no rule can allow it, and unless a deny fails closed it gets the implicit deny (ADR 0012).

Mandatory denies follow the same options. They default to no_match like any other deny; making the criteria of the shipped blocklists safety_critical, which defaults them to match, is #32 and #87.

§Modes

Evaluator::evaluate computes the enforce-mode decision, before anything relaxes it: its Decision::mode is always enforce. Evaluator::evaluate_in applies the effective mode of the device (crate::mode): the policy’s mode, the modes per object type, each rule set’s mode_override, each rule’s enforcement_override, the per-class control levels, connectivity, override sessions and emergency lockdown. It keeps the enforce-mode outcome in Decision::would_have_been.

§Determinism

Evaluation is a pure function of the policy and the object. Every stage chooses by keys that end with the unique rule ID, and the lists in a decision are sorted by rule ID, so the decision does not depend on the order of rule sets in the policy or of rules in a rule set. Only first_match and priority depend on rules’ order and priority.
