Source

pub fn evaluate_in( &self, subject: &Subject<'_>, state: &DeviceState, trace_id: TraceId, ) -> Option<Decision>

Decides one object on a device in state, applying the effective mode (crate::mode). Returns None when the device is disabled: the engine is not consulted, and nothing is decided or reported.

Decision::would_have_been is the enforce-mode outcome (evaluate). An object that enforce mode allows or ignores gets the same decision, in its effective mode. A block is relaxed in two layers, so that each relaxation is reported as what it is:

  1. Modes. Using the modes without the override session, every matching deny whose effective mode does not enforce is set aside, and the remaining rules are decided again. If that still blocks in an enforcing mode (an enforcing deny, a mandatory deny, or an enforcing implicit deny), the object is blocked by it: a blocklist in audit never lets through what another rule blocks. Otherwise the object runs as allowed_audit, naming the rule enforce mode decided by.
  2. Session. If layer 1 blocks and an override session is active, the same is done with the session’s modes, starting from the rules layer 1 kept. If that still blocks in an enforcing mode, the object is blocked. Otherwise it runs as allowed_override, naming the rule layer 1 blocked by: the one the session bypassed.

Every deny set aside is listed as overridden. A relaxed decision keeps the named rule’s effects except the notification, so the would-block event is still logged. Its directives are those of the last decision taken: if an allow decided it, the object runs with that allow’s containment, elevation and trust-source grants (which are then no longer listed as overridden); otherwise it has none, so nothing is terminated or requested. In learning, an object that only the implicit deny would block is a learning candidate.

Mandatory denies always enforce (ADR 0004, #125).
