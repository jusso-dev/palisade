palisade_policy::trace

Module privacy 

Source
Expand description

What a trace may say about the facts it read (#41, #18).

A trace leaves the agent, so it follows the privacy settings when it is built, never afterwards. Nothing unredacted is ever held in a Trace.

  • Object facts (hashes, signers, version resources) are written by default, because “why not allowed?” needs them.
  • Paths are written by default, after redaction. They can be withheld.
  • Context facts (user, device, session) are withheld by default.
  • A withheld value becomes a reference: its field, and a keyed digest (HMAC-SHA-256 under Privacy::digest_key) if a key is set, so two traces can be compared without revealing the value. With no key, the value is simply omitted.
  • Every value that is written first passes the Redactor: each match of a redaction pattern is replaced with [redacted]. Command lines (#7) will pass the same redactor when they become facts.
  • Every written value is cut to MAX_VALUE_CHARS characters.
