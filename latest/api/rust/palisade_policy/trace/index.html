The decision trace, explanations and policy simulation (#41).

Every decision can be explained. This module has three parts:

  • Trace (Tracer, Trace): a structured, bounded record of one evaluation. It lists the stages that ran, the rules that matched and the part each played, the rules that nearly matched and the criteria that failed them, the rules that would have matched but are disabled, the facts that were missing and what that did to the decision, the warnings, the effective mode with each step of its resolution, and the decision itself. Its JSON form is versioned (TRACE_SCHEMA_VERSION) and snapshot-tested.
  • Explain (explain): turns a trace into paragraphs and a table for people, rendered as plain text, Markdown or one short sentence, with localisable message templates.
  • Simulate (simulate, readiness, policy_test, effective): runs a policy, or a proposed change to it, over recorded facts and reports what would change, how ready devices are for enforce mode, whether policy-as-code tests pass, and what a device enforces.

§The trace is the evaluator’s

Tracer::trace calls Evaluator::evaluate_in, and the trace embeds that decision unchanged. The set of rules that matched is taken from the evaluator too. The trace then explains each rule by evaluating its criteria one by one, with the same compiled criteria and the same three-valued logic, without stopping early. It never decides anything itself. Tests check over random policies, facts and device states that the trace and the evaluator agree.

§Levels

LevelContents
minimalThe decision, the deciding rule and the effective mode. Built from the decision alone, with no further evaluation.
standardAdds the stages, every rule that matched, the deciding rule’s criteria, disabled rules that would have matched, rules whose scope excluded the subject, unknown facts, warnings, mode resolution steps, provenance, and a draft rule that would allow a blocked object.
fullAdds near misses, with the failing criteria and the observed and expected values, and every fact the evaluation read.

LevelPolicy chooses the level the agent records: minimal for an object that runs, standard for a block or a would-block, and full with a per-device debug flag or during a time-boxed diagnostic session. The simulator always records full.

§Bounds

A trace never grows with the size of the policy. Each list has a limit (limits), and what was left out is counted in Trace::omitted and in each entry’s *_omitted field. Every value is cut to privacy::MAX_VALUE_CHARS characters, and at most privacy::MAX_VALUES values of one fact are written. The JSON of a trace is at most limits::MAX_TRACE_BYTES; a test builds the largest trace the limits allow and checks it.

§Privacy

Facts are written as Privacy allows, when the trace is built: see privacy. The defaults write object facts and paths, withhold the user, device and session, and redact nothing.
