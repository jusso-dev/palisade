Module readiness 

Source
Expand description

Enforcement readiness (#41, #36): how many would-block events each device had over a period, and whether a move to enforce is safe.

A would-block is an event that enforce mode would block but the device’s mode let run (allowed_audit), recomputed by the simulator from the recorded facts, so it reflects the policy as it is now, not as it was when the event was recorded. An event blocked anyway is not a would-block: enforcing changes nothing for it.

readiness reports, over the events in [until − days, until):

  • every device, with its would-block count, ready when the count is at most max_would_block;
  • the objects with the most would-blocks, with a draft allow rule for each (the trace’s suggestion; the recommendation flow is #5);
  • the gate of #36: “N would-block events across M devices in the last D days”, and whether a readiness_ack is required before the transition, which is when N exceeds the configured threshold.
