Group provenance for traces and the effective view (#41, #37).

A device’s policy is built from the group hierarchy (crate::hierarchy::EffectivePolicy): each rule set comes from one or more nodes (the global node, a tenant, groups, dynamic groups, templates or the device), through a policy assigned to the node, a rule set library or a category, and a node below may have suppressed one of its rules. GroupProvenance carries that record, with the names of the nodes, into a Tracer and effective_view, so a trace says which groups a deciding rule came from and the view says it for every rule.

The group steps go before the policy, rule set and rule steps, outermost node first: InheritanceStep::node is the node’s kind (global, tenant, group, dynamic_group, template or device), via says how the node contributed, and outcome is contributed, or for the node that suppressed the rule suppressed or suppression_overridden.

Names follow the trace’s privacy settings: every name passes the Redactor and is cut to MAX_VALUE_CHARS characters, as policy, rule set and rule names do, and the ID is always written. A node is named only by its configured name; group membership of the user or device is never part of it.
