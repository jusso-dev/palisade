Module simulate 

Source
Expand description

The policy simulator (#41): replays recorded facts against a policy and a candidate, and reports what would change.

§Inputs

A FactsSnapshot is one recorded decision’s inputs: the object’s type, facts and path variables, the user, device and session, and the device’s state. Snapshots come from events, from a YAML or JSON test file, or from a facts corpus exported from a device inventory (#5); all three use this one versioned format (FACTS_SCHEMA_VERSION), read by read_snapshots. A snapshot of another major version is rejected, never guessed at. A fact a snapshot lacks is absent, so a rule that needs it evaluates to unknown, exactly as on the agent.

§Candidates

A Candidate is another policy document (a draft revision), the current document with a ChangeSet applied, or the current policy in another mode (audit to enforce). It is validated before it is simulated.

§The same evaluator

Every decision is made by Evaluator::evaluate_in, the function the agent calls, on the same validated document. The simulator has no logic of its own: given the same facts and device state, it decides what an agent decides. The canonical bundle (#43) will be loaded into the same ValidatedPolicy.

§Determinism

Events are evaluated in parallel, a chunk per thread, and the results are sorted by event ID, so the report does not depend on the number of threads. Duplicate event IDs are rejected.
