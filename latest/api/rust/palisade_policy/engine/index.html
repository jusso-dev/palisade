Module engine

The engine the agent decides through (#42): a policy snapshot that is swapped atomically, the decision cache, the lazy fact protocol and the per-decision watchdog.

An Engine holds the current Snapshot: one validated policy with its compiled Evaluator. Engine::load builds a new snapshot off the hot path and swaps it in with one atomic store (arc-swap). A decision that started on the old snapshot keeps it until it finishes; the next one sees the new policy. Reading the snapshot takes no lock.

Engine::evaluate decides one object:

  1. A cache hit returns the cached decision (cache).
  2. Otherwise the evaluator decides with the facts computed so far, or returns NeedFacts with what to compute next (crate::evaluate::index).
  3. A watchdog bounds the time spent. Mandatory denies are evaluated first; the budget is checked after each match tree, and once it is spent no further tree is evaluated. A mandatory deny that already matched then decides, as always (ADR 0004). If the mandatory tier was not finished, the object is blocked. Otherwise the decision falls back to TimeoutAction: block (the default when the object’s type is enforced), or allow_audit. The result names the slow rule for the policy.eval_timeout health event (EvalTimeout).

The engine is Send + Sync. Time comes from the caller (Clock), so the engine stays pure and tests can drive time.
