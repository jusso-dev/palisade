Reusable libraries: objects that policies reference instead of copying (#37).

A Library is one version of a named object: a rule set, an application definition, a match fragment, or a set of hashes, publishers, paths, principals, devices, networks or schedules, or a message template. Each version is immutable; editing makes a new version with the same LibraryId.

§References

A match tree refers to a library with a ref node (LibraryRef): an ID and a pin. pin: latest (the default) tracks the newest version; pin: 3 stays on version 3 until the reference is changed. A reference is resolved when the effective policy is built (crate::hierarchy), and the resolved version of every library used is recorded, so the same inputs always give the same policy. A policy document that is evaluated never holds a reference: validation rejects one (unresolved_ref).

Only these kinds can be referenced from a match tree. Each is replaced by a tree:

KindReplaced by
match_fragmentits tree
application_definitionits one tree, or any of its trees
hash_set, publisher_set, path_setone criterion on the set’s field, or any of criteria of at most 25 values each

Rule set libraries are assigned to a hierarchy node, not referenced from a tree. Principal, device, network and schedule sets are read by scopes (#38), and message templates by notifications (#147): they are looked up with Catalogue::resolve and cannot appear in a tree (ref_kind_not_allowed).

§Cycles and limits

A library may reference other libraries: a rule set’s rules, a fragment and an application definition may hold ref nodes. The reference graph is over library versions, with each pin resolved. Catalogue::new rejects every cycle in it (library_cycle), naming the path, such as `Script hosts` v2 -> `Document editors` v1 -> `Script hosts` v2. References nest at most limits::MAX_REF_DEPTH deep, and expanding one rule’s tree produces at most limits::MAX_EXPANDED_NODES nodes, so a chain of fragments that each use the next twice cannot grow without bound. Validation of the expanded rule then applies the usual tree limits.

§Scope, ownership and copies

A library is global (installation-wide, read-only to tenants) or belongs to one tenant. A tenant’s trees may use global libraries and its own; a global library may use only global libraries. Only an installation administrator edits a global library. A tenant library is edited by its owner or a tenant administrator; anyone in the tenant may view, duplicate and attach it (Library::can_edit, Library::can_use). A read-only (curated) library is never edited in place: Library::duplicate makes an editable copy that records derived_from.

§Deleting

crate::hierarchy::ValidatedHierarchy::check_delete refuses to delete a library that anything references, and lists every referrer. The 30-day soft delete is the server’s (#10).
