Expand description

The identity facts a criterion can test (#31).

This is the part of the #31 catalogue that has a matcher: hashes, the signer and its certificates, the path and the version resource. The other families (packaged apps, installers, ownership, origin and process relationships) arrive in later minor versions, each with its facts and matcher.

The SHA-1 thumbprint of the chain’s root certificate. Compatibility only (ADR 0008).

§

SignerTbsHash

The hash of a chain certificate’s tbsCertificate, under the certificate’s own signature digest (40, 64, 96 or 128 hex digits). It identifies that one certificate: the tbsCertificate includes the serial number and the validity period (RFC 5280), so a certificate reissued with the same key has another TBS hash, and each issue needs its own rule; signer.spki_sha256 names the key across every certificate that carries it. signer.position says which certificate. A 40-digit (SHA-1) value is compatibility only (ADR 0008).

§

SignerEku

The extended key usages of the leaf certificate, as dotted OIDs, such as 1.3.6.1.5.5.7.3.3 (code signing). A leaf without the extension has none.

§

SignerSpkiSha256

The SHA-256 of a chain certificate’s DER SubjectPublicKeyInfo: its public key (#318). Unlike the TBS hash it stays the same when a certificate is reissued for the same key, so a deny on a stolen key’s hash also blocks every reissue. signer.position says which certificate. A key above the leaf belongs to a certificate authority, which vouches for everything it signs.

MetaLegalCopyright

The LegalCopyright string from the version resource (#328).

MetaLanguage

The language and code page of the version-resource block the other meta.* strings were read from, as its key is written: eight hex digits, such as 040904b0 (#328).

§

MetaFileNameFallback

The file’s effective name (#328): the first of the original file name, internal name, file description and product name that the version resource has, or the name on disk when it has none.

§

MetaFileSize

The file’s size in bytes, as a whole number (#328).

MetaPeMachine

The PE image’s COFF machine, by name: i386, amd64, arm64, arm64_ec, arm64_x, arm_nt and so on (#328).

§

MetaPeSubsystem

The PE image’s subsystem, by name: windows_gui, windows_cui, native, efi_application and so on (#328).

§

MetaIsDotnet

Whether the PE image is a .NET assembly: it has a CLR runtime header (#328).

§

MsiProductCode

A Windows Installer package’s ProductCode (#328), a GUID. Compared as a GUID: braces and case do not matter.

§

MsiUpgradeCode

A Windows Installer package’s UpgradeCode (#328), a GUID shared by every version of a product.

§

MsiProductName

A Windows Installer package’s ProductName (#328). Free text the author chooses.

§

MsiManufacturer

A Windows Installer package’s Manufacturer (#328). Free text the author chooses: never a publisher.

§

MsiProductVersion

A Windows Installer package’s ProductVersion (#328).

§

MsiPackageCode

A Windows Installer package’s PackageCode (#328): the GUID of one build of the package.

§

PathDriveType

The drive type of the file’s volume, as the OS reports it (#328): fixed, removable, network, cd_rom or ram_disk. An unknown drive type is a missing fact.

§

PathBus

The bus of the disk the file’s volume is on (#328): usb, sata, nvme, scsi, sd, virtual, file_backed_virtual, iscsi and so on. An unknown bus is a missing fact.

§

PathIsUnc

Whether the file is on a network share: its path, or the other form of it (a mapped drive’s UNC path), is a UNC path (#328).

§

PathIsAds

Whether the object is an alternate data stream of a file (#328).

§

PathShare

The \\server\share a file on a network share is under (#328), from its UNC path. A file on no share has none, so equals does not match it.

§

PathUserCanChangeAcl

Whether some non-administrator may change the permissions or the owner of the file or a directory above it (#328).

§

MetaDetectedType

What the file’s content is, from its bytes (#30, #328): pe, msi, script, zip, lnk, text and so on, in palisade-fileid’s names. unknown is a missing fact.

§

MetaExtensionType

What the file’s name claims it is, from its extension (#30, #328): one of the Self::MetaDetectedType names, or none (no extension), inert (a document or media extension) or other. A PE renamed to .pdf has meta.detected_type pe and meta.extension_type inert.

Source

pub const fn strength(self) -> Option<Strength>

How firmly a positive test of this field identifies an object (#31). None for a context field (#33), which identifies no object.

A certificate authority vouches for every file it signs, so the issuer, the PCA, the root thumbprint and the EKUs are weak alone. A TBS hash is strong here, as #31 rates it, and so is a key hash (#318); validation counts either that may name a CA certificate (position other than leaf) as weak in a rule that lets an object run. A leaf key hash names whoever holds the private key, across every certificate issued for it.
