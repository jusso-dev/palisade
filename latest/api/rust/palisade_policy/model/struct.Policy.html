Expand description

The decision part of a policy: which rule sets apply, and how.

Fields§

§id: PolicyId

Stable ID. Renaming the policy never changes it.

§name: String

Display name: 1 to 128 characters, trimmed, no control characters. Uniqueness within a tenant is checked by the server (#10).

§description: Option<String>

Free-text description, at most 4096 characters.

§revision: u64

Monotonic revision, raised by the server on every change (#10).

§precedence_model: PrecedenceModel

How matching rules are combined (#35, ADR 0004).

§precedence_options: PrecedenceOptions

Settings of the precedence models (#35). An option the selected model does not use is ignored, with a warning.

§mode: Mode

The base enforcement mode (#36). disabled is not allowed: only a device can be disabled, with a reason and an expiry.

§mode_options: ModeOptions

The modes per object type and while disconnected (#36).

§settings: PolicySettings

Typed settings. Every field has a documented default.

§rule_sets: Vec<RuleSetId>

The rule sets that apply, in order, by ID.

§scope: Option<Scope>

Who, where and when the whole policy applies (#38). Every rule must also be in this scope.

§rule_set_scopes: Vec<RuleSetScope>

The scopes of rule set assignments (#38): each rule of the set must also be in every one of them. At most one entry per rule set.

§location_profiles: Vec<LocationProfile>

Named network locations that scopes test with location_profile (#38).

§metadata: Metadata

Governance metadata (#40).
