Presets: match trees for the recommended rule forms (#31, #33).

A preset builds an ordinary match tree, so a policy that uses one is validated, evaluated and ranked by precedence like any other.

Structs§

PublisherProduct
The publisher rule publisher_product (#31, ISM-1471): a signer’s publisher and a product name, optionally narrowed by the original file name and a file-version range. This is the recommended form of an allow rule: a publisher alone trusts everything the publisher signs.

Functions§

metarule
The preset metarule (#33): one positive identity criterion, AND-ed with up to four context criteria, the one-to-five criterion form other products call metadata rules. The tree is an all of the identity, then the context criteria in order; with no context it is the identity alone.
publisher_product_version
The preset publisher_product_version (#33): PublisherProduct with a lowest file version, so a rule allows a product from a release on.
signed_in_directory
The preset signed_in_directory (#33): files under a directory, at any depth, that a publisher signed, optionally narrowed to one product. The tree is an all of path.directory starts_with the directory (which ends at a component boundary, so C:\Tools does not cover C:\ToolsX), signer.publisher equals the publisher, and meta.product_name equals the product if set. A path only identifies a file in an allow where users cannot write it (#31), so the signer is what the rule rests on there.
