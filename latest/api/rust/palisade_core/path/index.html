Lexical normalisation of Windows paths (#32).

Facts and rule patterns both pass through normalize, so two spellings of one path compare equal. The rules, in order:

  1. / becomes \.
  2. The \\?\, \??\ and \\.\ prefixes are removed. \\?\UNC\server\share becomes \\server\share, and \\?\GLOBALROOT\Device\... becomes \Device\....
  3. An NT device path (\Device\HarddiskVolume3\x) becomes a drive path when a VolumeMap entry names its device. The device name must end at a separator, so \Device\HarddiskVolume33 never matches an entry for \Device\HarddiskVolume3. An unmapped device path keeps PathKind::Device.
  4. Repeated separators collapse, and a leading run of two or more becomes the two that start a UNC path. A trailing separator is removed, except after a drive root (C:\).
  5. In an absolute path, . components are removed, and .. removes the component before it. .. never climbs above the root (C:\..\x is C:\x), and never removes the server or share of a UNC path. Relative paths keep . and ...
  6. NTFS stream-type suffixes that name the object itself are removed: ::$DATA (and :name:$DATA becomes :name) on the last component, and ::$INDEX_ALLOCATION or :$I30:$INDEX_ALLOCATION on any component. A chain of them (a::$INDEX_ALLOCATION::$DATA) is removed whole. These spellings are the same object on disk, so leaving them would let a file escape a path rule. Removing them never turns a relative path into an absolute one: a . component is kept in front when the rest would read as a drive, device or NT prefix.
  7. The drive letter is upper-cased. Nothing else changes case: case folding is part of comparison, not of normalisation.

Trailing dots and spaces are kept, because the file system keeps them for names created through the \\?\ prefix: a.exe. is not a.exe. A named stream (file.txt:payload) is kept, and NormalizedPath::stream reports it. Short (8.3) names are not expanded here: that needs the file system, and the agent supplies the long path (#4).

Normalisation is idempotent: normalising a normalised path gives the same path.
