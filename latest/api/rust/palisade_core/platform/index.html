The platform abstraction (#29): traits for everything the agent reads from the operating system.

Decision logic (evaluation-context building, rule expiry, schedules, OTP windows) reads the system only through these traits, so it runs in unit tests on any OS against in-memory mocks (palisade_core::test_util, with the test-util feature). The Windows implementations live in the agent.

The traits are deliberately small: each method is one OS query, returns plain data, and does no caching. Caches (the directory group cache, the process tree) belong to the agent, which builds the resolved context that evaluation receives. New methods are added under ADR review, as consumers need them.

The hot evaluation path is generic over Platform (static dispatch, for the evaluation budget in #42). Every trait except FileSystem is also object safe, for code where dynamic dispatch is fine.

Paths are Windows paths as text (C:\Windows\System32\cmd.exe), and SIDs are in their canonical text form (S-1-5-18). Both are compared case-insensitively by the Windows implementations, and by the mocks.
