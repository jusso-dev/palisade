Host notifications and stop gating, independent of the service control manager (SCM).

The SCM delivers controls to palisade_agent::service on its own thread. That module translates each one into a StopRequest or a HostEvent, and the host publishes host events to every running subsystem through SubsystemContext::host_events. This module holds the platform-independent half, so the routing and the gating rules are tested on every OS.

Volume arrival and removal (DEVICEEVENT, for inventory #60) need a device-interface registration that the windows-service crate does not offer, so they arrive with a control handler of the agent’s own in palisade_agent::ffi.
