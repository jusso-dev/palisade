Expand description

Signature lookup and chain validation through palisade_fileid.

Fail closed (ADR 0018):

  • a file that cannot be read, or is larger than the size limit, is an error, never “unsigned”; a file that starts like a PE image (MZ) but does not parse, or whose certificate table cannot be read, is VerificationError::MalformedSignature, never “unsigned”;
  • a file whose hash is revoked (its flat or Authenticode SHA-256 or SHA-1, under settings.revocation) is VerificationError::RevokedByHash, on the embedded and the catalog path alike;
  • a signature or catalog match that relies on SHA-1 (an image digest, a signer digest, a member digest or a catalog’s own signature) is VerificationError::WeakHashAlgorithm, never Ok, so no allow rests on it (ADR 0008);
  • with no catalog store loaded, SignatureVerifier::catalog is ErrorKind::Unsupported, not “no catalog signature”; and when the store is incomplete (a catalog was unreadable, or a load error or limit left catalogs or members out), a miss is an error too, since the file could be in what is missing;
  • a catalog match whose validity was never judged is not Ok.

When things are judged. Embedded signatures are judged on every call, against settings and clock. A catalog’s own signature (its chain’s expiry, timestamps and revocation) is judged once, when the store is built, against the ValidityOptions given to its builder: rebuild the store to re-judge it (the catalog index refresh, #60, #65). The rest of a catalog verdict is judged on every call: revocation of the file’s own hash and SHA-1 use against settings, and trust as the store recorded it.

Signing times and expiry are judged against clock. The agent’s anchored time and clock floor (ADR 0018, #220) replace the plain wall clock when they land.

pub fn with_catalogs<'a>( self, store: CatalogStore, loads: impl IntoIterator<Item = &'a LoadReport>, ) -> Self

Uses store for catalog lookups. Load it with palisade_fileid::catalog::CatalogStoreBuilder, with the trust configuration and validity options of each source: a match is only Ok if its catalog is trusted and its validity was judged.

loads are the reports of every load call that built it. If any reports an error (I/O, a size, byte, count, depth or entry limit, a file that changed) or dropped errors, or the store holds an unreadable catalog or a truncated index, the store is incomplete and a catalog miss is an error, not “no catalog signature”.
