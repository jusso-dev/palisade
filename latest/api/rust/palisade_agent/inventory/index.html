Module inventory 

Source
Expand description

The file inventory (#60): every executable-content file on the endpoint’s volumes, with its identity, first-seen, last-modified and last-executed times, kept current from the change journal.

  • entry: the inventory record (entry::InvEntry) and its identity summary.
  • scope: what the inventory covers, and the phase-1 prefilter by name.
  • store: the storage trait (ADR 0007 leaves the backend to a spike) and an in-memory store.
  • track: changes coalesced per file, applied to the entries, and what each needs next (identify, reassess the location).
  • engine: the initial scan with checkpoints and a throttling seam (#65), journal polling, and reconciliation when the journal cursor is lost.
  • subsystem: the inventory subsystem, over the volumes a subsystem::VolumeProvider gives: on Windows every fixed NTFS or ReFS volume, read by file ID through palisade_fileid::win::journal.

changes_from_journal turns change-journal records (palisade_fileid::fsctx::ntfs, read by palisade_fileid::win::journal on Windows) into track::Changes.

The change one journal record reports, on the volume volume_serial. The path is left for the caller to resolve from the parent reference, and is None here. A rename’s old-name record is not a change of its own: the new-name record that follows carries it. Returns None for records with nothing the inventory tracks.
