palisade_agent::inventory

Module engine 

Source
Expand description

The inventory engine: the initial scan, reconciliation and change tracking of one volume, over a VolumeSource and an Identifier.

The source is the OS: on Windows the master file table and the change journal (palisade_fileid::win::journal); in tests, a scripted volume. The engine itself is portable, so every path through it is tested on any OS.

  • Engine::scan lists every file of a volume in batches, keeps the candidates (super::scope::InventoryScope::candidate), and records them. It saves a ScanCheckpoint every CHECKPOINT_FILES files or CHECKPOINT_INTERVAL, so a restart resumes instead of starting again, and asks the Throttle before every batch: the resource budgets (#65) plug in there.
  • Engine::poll reads the journal from the saved cursor and applies the changes (super::track). If the journal was replaced, or wrapped past the cursor, it reconciles the volume instead (a scan with Discovery::Rescan that marks files no longer listed as deleted) and reports that it did.
