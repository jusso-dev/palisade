Module supervisor 

Source
Expand description

The supervisor: ordered start, restart with backoff, panic containment and ordered shutdown with deadlines.

  • Start order follows the declared dependency graph, which must be acyclic. Ties keep registration order, so the order is deterministic. A subsystem starts once all its dependencies are ready.
  • Failure means a run returned an error, returned before a stop was requested, panicked, or was not ready within its start_timeout. Each run is its own tokio task, so a panic is caught at the task boundary (the same catch_unwind boundary that tokio::spawn provides) and affects that subsystem only. The process panic hook (crate::host::install_panic_hook) logs it with a backtrace.
  • Restart follows exponential backoff from RestartPolicy::initial_backoff to RestartPolicy::max_backoff (1 s to 5 min). A run that stayed ready for RestartPolicy::stable_after resets the backoff.
  • Circuit breaker: RestartPolicy::panic_limit panics within RestartPolicy::panic_window (3 in 10 minutes) mark the subsystem SubsystemStatus::Failed; it is not restarted again. Errors alone never trip the breaker: they keep retrying at the maximum backoff. Panics that a subsystem catches itself, such as one per parsed file, never reach the supervisor and do not count (ADR 0012).
  • Agent state is derived from the subsystems. FailSafe as soon as a critical subsystem has failed, even during startup. Otherwise Starting until every subsystem has had its first outcome, then Degraded if any subsystem is not running, and Running if all are. A dependency that fails or restarts does not stop its running dependents. In a safe-mode boot (Supervisor::safe_mode), Running and Degraded are reported as SafeMode instead; FailSafe still wins.
  • Shutdown first stops every subsystem that is not running (waiting, restarting or failed), so nothing starts during shutdown. It then stops the running subsystems in reverse start order, so dependents stop before what they depend on. Each gets Subsystem::stop_timeout, capped by the overall budget; a subsystem that misses its deadline is aborted, so shutdown always finishes within the budget. A running subsystem that fails while others are still stopping is not restarted, and its failure is reported in the ShutdownReport.
  • Timeouts longer than about ten years are capped, so no deadline computation can overflow.
