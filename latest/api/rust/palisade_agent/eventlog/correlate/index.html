Module correlate 

Source
Expand description

Grouping decision records with their per-signature records (#58).

The OS code integrity log writes a block or audit decision (3076, 3077) followed by one signature record (3089) per signature, all with the same correlation activity ID. The decision says how many signatures follow (TotalSignatureCount). Script hosts do the same in the rule-collection log (8028, 8029, then 8038 per signature). The Correlator holds each decision until all its signatures have arrived, or until DEFAULT_WAIT (2 s) has passed, and then releases the group for mapping. Every other record passes straight through.

Signature records that arrive before their decision are held too, for the same window, so the order in which the subscription delivers them does not matter.

Limits, all counted, never silent: at most MAX_PENDING groups wait at once (the oldest is released early, incomplete, when it is full); a group holds at most 64 signatures, the schema’s limit; and orphan signature records that never meet their decision are dropped when their window ends.

Before correlation, a token bucket (RateLimiter) bounds the rate (2,000 records a second by default), so an audit storm cannot exhaust memory. Records over the rate are dropped and counted.
