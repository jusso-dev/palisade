The component model: the Subsystem trait and its run context.

A subsystem is one long-running part of the agent (policy cache, server comms, event pipeline and so on). The Supervisor starts subsystems in dependency order, restarts them when they fail and stops them in reverse order with a deadline.

The lifecycle of one run:

  1. The supervisor calls Subsystem::run once every dependency is running.
  2. The subsystem initialises and calls SubsystemContext::set_ready. Dependents start only after that. A run that is not ready within Subsystem::start_timeout is aborted and counts as a failure.
  3. It works until SubsystemContext::stopped resolves, then finishes by the returned deadline and returns Ok(()). This is the stop(deadline) step of #56. A subsystem still running at the deadline is aborted at its next .await.

Returning before a stop is requested, with or without an error, or panicking, is a failure: the supervisor restarts the subsystem with backoff. Subsystems must not block async worker threads; blocking work goes through tokio::task::spawn_blocking (ADR 0009).
