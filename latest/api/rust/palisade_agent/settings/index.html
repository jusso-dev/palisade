Configuration layers and advanced settings (#56).

The effective configuration is built from four layers, lowest priority first:

  1. built-in defaults (AgentConfig::default);
  2. the install-time file %ProgramData%\Palisade\agent.toml (#57);
  3. the agent settings delivered with policy (PolicySettings, #61);
  4. local overrides, %ProgramData%\Palisade\overrides.toml, applied only while the policy layer sets allow_local_overrides = true.

resolve merges them and records where each value came from, for palctl config show (Effective::render). Each layer is parsed strictly (unknown keys and wrong types are errors), and the merged result is range-checked as a whole. Ranges are checked on the merged result, not per layer, so a layer cannot be rejected for a value a higher layer replaces.

Fail closed (ADR 0018). The policy layer and the overrides are trusted only as far as their source:

  • Without a policy layer, overrides are not allowed.
  • An overrides file that exists but cannot be shown to be writable by SYSTEM and administrators only is ignored and reported (OverrideStatus::Untrusted). The check is the caller’s (OverrideSource::protected); on Windows it is the file’s DACL, read through palisade_fileid.
  • If the merged result is out of range because of the overrides, the overrides are dropped and reported rather than stopping the agent; if it is out of range without them, the policy layer is dropped the same way. The install-time file was range-checked when it loaded.

Advanced settings (agent.advanced.*) are a typed key/value map delivered with policy. ADVANCED_SCHEMA lists each name, type and range. Unknown keys are logged and ignored, and a value of the wrong type or out of range is logged and replaced by the default, so a bad engineering key never stops the agent and never takes a value nobody validated.
