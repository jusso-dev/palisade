Process creation and image-load monitoring (#59).

The parts that read untrusted bytes or hold state are portable, have no unsafe code, and are tested (and fuzzed) on every OS:

  • kernel decodes the kernel process provider’s ETW records.
  • tree is the process tree, keyed by process ID and creation time, so a reused process ID never corrupts ancestry.
  • cmdline captures, redacts and truncates command lines.
  • monitor is the state machine that turns records into events.
  • output is what it emits, and the seam to the event pipeline (#63): a TelemetrySink, with a bounded, non-blocking ChannelSink.

On Windows, windows is the subsystem that runs the ETW session through ffi::etw (the agent’s allowlisted unsafe module, ADR 0011) and feeds the monitor.

Functions§

health_of
The monitor’s health from its counters: degraded while the OS reports lost events, records are dropped or not decoded, or status reports a problem. Losses are always visible, never silent.
os_subsystems
The subsystems that read the OS, for the console and service runs. On Windows, the process monitor. Its events go to a DiscardSink until the event pipeline (#63) takes them, so the sink-drop counter in its health shows the volume waiting for the pipeline.
