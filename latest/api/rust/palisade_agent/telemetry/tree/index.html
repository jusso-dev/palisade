Module tree 

Source
Expand description

The in-memory process tree (#59).

Every process is keyed by its ProcessKey: the process ID and its creation time, so a reused process ID never makes an unrelated process look like a parent or an ancestor. Where the OS supplies process sequence numbers (unique per boot), they are used first.

A parent is linked only when it is provably the parent:

  • its sequence number is the one the child’s start event names; or
  • it has the parent ID the child names, was created no later than the child, and had not exited when the child was created.

Otherwise the child has no parent in the tree. Unknown ancestry is reported as unknown, never guessed (ADR 0018).

Exited processes stay for a retention period (10 minutes by default) so late events (the OS code integrity log, #58) can still be correlated, then are evicted. The tree holds at most a fixed number of processes (200,000 by default). When it is full, the process that exited first is evicted early; if every process is still running, the new one is not recorded and ProcessTree::rejected counts it.
