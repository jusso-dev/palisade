palisade_agent::policy_cache

Module store 

Source
Expand description

The policy cache on disk (ADR 0007): the active, previous and pending files under the agent’s store directory, and the copies of the anti-rollback record.

Every write goes to a temporary file that is flushed to disk, then renamed over its target. On Windows the rename is MoveFileExW with MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH, so it is durable before the call returns. Elsewhere it is rename(2) followed by a flush of the directory. A power loss therefore leaves either the old file or the new one, never a torn file.

The directory must be SYSTEM-only (#220); the installer creates it. The files are authenticated by their signatures, not by their permissions. With a Sealer (#326) each cache file is sealed with AES-256-GCM under a data key whose keyring is protected by machine-scope DPAPI; the opened bytes are still the signed envelope, verified as before.

The anti-rollback record copies, each protected by a Protector (machine-scope DPAPI) and kept in its own RecordSlot (#326): a file next to the cache and a registry mirror on Windows. A copy that does not unprotect reads as corrupt, never as missing, so replacing or damaging one is reported (tamper.policy.rollback_suspected).
