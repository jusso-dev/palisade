palisade_agent::policy_cache

Module builtin 

Source
Expand description

The built-in policies the agent runs when no bundle loads (ADR 0018).

  • First install: no policy was ever accepted. Audit mode, so nothing is blocked before the first bundle arrives; every would-block decision is reported (PolicyMissing). The mandatory blocklists of #87 join it when the agent ships them.

  • Emergency: a policy was accepted before, but neither active nor previous loads (#225, ADR 0018). It allows only:

    • binaries signed by the operating system’s publishers, in the protected OS locations, through the agent’s system_baseline (palisade_policy::unknown::baseline). That is narrower than “every OS-signed binary”: user-writable folders inside the Windows directory and binaries outside the OS locations stay blocked;
    • Palisade’s own images, each pinned by SHA-256 and publisher (SelfPin), so a copy signed by someone else or a re-signed file with other content is not allowed;

    and blocks everything else. It runs in enforce mode where a Palisade enforcer exists, and in audit mode under the native_only strategy, where nothing in Palisade’s layer enforces it (Enforcement). It is only ever applied to Palisade’s own decisions: it never touches the installed OS-native policies (ADR 0018, “Emergency policy and the native layer”).

Every input that does not build (an invalid pin, baseline facts that do not fit) is left out, which only removes an allow: the emergency policy is never weaker than “block everything”, and with no facts at all it is exactly that. The tests check every combination builds.
