The axum router and the tower middleware stack for one listener.

Layers, outermost first:

  1. Request ID and error normalisation. Accepts a well-formed Palisade-Request-Id from the client or generates a random one, echoes it on the response, and turns every error response into an RFC 9457 problem document (see crate::problem).
  2. Trace. One span per request with request_id, listener, method and the matched route template (never the raw path or query, which may carry tokens), and one log line per response with the status and latency.
  3. Panic guard. A panicking handler becomes a 500 problem; the panic message stays in the server log.
  4. Timeout. A handler that runs past the listener’s request_timeout_secs is cancelled with a 503 problem.
  5. Body limit. A body larger than the listener’s body_limit_bytes gets a 413 problem, whether the size is declared up front or only discovered while streaming.

Tenant, principal, authentication, rate-limit, CORS and compression layers join this stack with the API work in #185, #130 and #229.
