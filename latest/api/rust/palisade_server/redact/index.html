Log redaction (#227): a second line of defence behind “never pass a secret to a log macro”.

RedactingMakeWriter wraps the log writer. Every complete line it is given goes through redact_line before it is written:

  • Sensitive field names. In a JSON line, any object member whose name has a segment (split on _, - and ., compared without case) in SENSITIVE_SEGMENTS has its value replaced by "[REDACTED]", whatever its type. This covers event fields and the fields of every span on the line. A name whose last segment is file or path is exempt: secrets are configured by path (tls.key_file, database.password_file) and the path is what an operator needs to fix a problem.
  • Secret-looking values, in every string of a JSON line and in any line that is not JSON: admin API tokens (pal_<env>_<id>_<secret>, #227) keep their non-secret pal_<env>_<id>_ prefix and lose the rest, an HTTP Bearer or Basic credential loses its value, and a PEM PRIVATE KEY block loses its body.

Redaction never fails open by dropping a line: a line it cannot parse as JSON is still scanned for secret-looking values and then written.
