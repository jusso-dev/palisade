Module health 

Source
Expand description

Process health, as reported by the liveness and readiness probes.

  • /healthz (liveness) answers 200 whenever the process can serve a request at all.
  • /readyz (readiness) answers 200 when every configured listener is bound on every address it should be, and the server is not shutting down. Otherwise it answers 503. The body is a small JSON document with a status and a list of indicators. It carries no addresses.

Indicators:

IndicatorMeaningReadiness
listener_unbound:<name>The listener has an address it could not bind yet, or a named interface with no address503
public_exposure:<name>deployment.profile = "overlay" and the listener is reachable on a public address200, status degraded
shutting_downShutdown has started and connections are draining503
database_down[database] is configured and the last check could not reach it as the runtime role503
database_schema:<verdict>The schema is behind (pending migrations), newer than this binary, or damaged (checksum mismatch or a failed migration)503
database_role_unsafeThe runtime login could bypass row-level security (superuser, BYPASSRLS, owns schema objects)503
clock_offsetclock.ntp_servers is set and the clock is further from NTP than clock.max_offset_ms (1 s by default)200, status degraded
clock_unknownclock.ntp_servers is set and no server gave a valid reply (also before the first check)200, status degraded
