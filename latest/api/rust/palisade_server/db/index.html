The Postgres layer: connection pools, embedded migrations, the schema-version check and the per-transaction tenant scope.

ADR 0006 (docs/adr/0006-server-database.md) decides the model: one shared schema, tenant_id on every tenant-owned row, and row-level security (RLS) that the database enforces for every query. This module supplies the pieces the rest of the server builds on:

  • Database::connect_runtime: the pool for the runtime role, the only login the server serves requests with. That role owns nothing and cannot bypass RLS. start refuses to start with a role that could, and readiness keeps checking.
  • migrator: forward-only migrations from migrations/, embedded in the binary. They run as the separate migration role, which owns the schema (migrate_up).
  • schema_state: compares the applied migrations with the embedded ones, so the server refuses to start against a schema newer than itself, and migrate verify reports checksum mismatches.
  • TenantTx: the only way to run tenant-scoped queries. It begins a transaction and sets palisade.tenant_ids with SET LOCAL semantics before any query can run, so the scope never leaks to the next user of a pooled connection.

Every query is a fixed SQL string with typed bind parameters. Nothing here builds SQL from values.

Palisade sets every connection parameter from its own configuration, so these are refused rather than silently mixed in: a password or a TLS client key would bypass the *_file rule, and PGOPTIONS could change session settings such as row_security.

Functions§

check_migration_role
Fails unless the current login may run migrations: not a superuser, palisade_runtime exists, the login and palisade_runtime are not members of each other, and the login owns the palisade schema if it already exists. It runs before anything is created, so a mistaken run as another role changes nothing.
check_pg_env
Fails if the process environment sets any REFUSED_PG_ENV variable.
check_runtime_role
Fails unless the current login is fit to be the runtime role.
connect
Opens one connection, giving up after timeout.
connect_migration
Connects once with the migration login.
connect_options
Connection options for one login. The password is read from its secret file here and handed to the driver; it is never logged or returned. The driver keeps its own copy for reconnecting, which is not zeroised (#227).
health_check
The database state for readiness, with the reason when it is not up. The whole check is bounded by the connect timeout, so a stalled connection or a lock on the history table reports the database as down instead of freezing readiness at its last state.
migrate_up
Applies every pending migration, as the migration role. Refuses a wrong role, and a schema that is newer than this binary or damaged, before changing anything.
migration_options
Connection options for the migration login.
migrator
The embedded migrations, in version order, with the history table in the palisade schema.
preflight
Checks everything about the database configuration that can be checked without connecting: the refused PG* variables, every password file, and the CA file. check-config and serve run it before binding, so a bad file is a configuration error (exit 2).
refused_env
Names of REFUSED_PG_ENV variables for which is_set is true.
role_facts
Reads RoleFacts for the current login.
schema_state
Compares the applied migrations with migrator. Works for the migration role and the runtime role (which may read the history). A database with no palisade schema yet has nothing applied.
start
Start-up database work for serve, run before any listener binds.
verify_structure
Structural checks on the applied schema, beyond the checksums: every table in the palisade schema that has a tenant_id column, or is the tenant table, must have row-level security enabled and forced and at least one policy; every foreign key from a tenant-owned table to another tenant-owned table must include tenant_id; and the runtime group must not own anything. Returns one message per problem.
watch
Runs health_check every interval and records the result in health, logging each change, until the task is aborted.
