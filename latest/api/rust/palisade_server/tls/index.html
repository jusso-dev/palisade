Module tls 

Source
Expand description

TLS for every listener.

All listeners terminate TLS with rustls and the ring provider (ADR 0008). There is no plaintext listener and no option to add one. The provider is cut down to an explicit allowlist of cipher suites and key exchange groups, so a future default change in rustls cannot widen the policy:

ProfileTLS 1.3 suitesTLS 1.2 suitesKey exchange
defaultAES-256-GCM-SHA384, AES-128-GCM-SHA256ECDHE-ECDSA/RSA with AES-256-GCM or AES-128-GCMX25519, P-256, P-384
asd-strictAES-256-GCM-SHA384ECDHE-ECDSA/RSA with AES-256-GCM-SHA384P-384

ChaCha20-Poly1305 is left out because it is not on the ASD-approved list. TLS 1.0 and 1.1 are not implemented by rustls at all. TLS 1.2 requires the extended master secret extension.

The agent listener requires a client certificate that chains to the configured agent CA bundle. Checking that certificate against the enrolled device record and revocation state is enrolment work (#223).
