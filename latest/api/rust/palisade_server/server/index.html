Source

The running server: listener supervision, connections and shutdown.

Each configured listener has a supervisor task. The supervisor resolves the listener’s bind target to socket addresses, binds each one it does not have yet, and runs an accept loop per bound socket. It repeats this on a timer, so:

  • an address that cannot be bound yet (an overlay interface that is not up, an address not assigned yet, a port still in use) is retried with exponential backoff, and health shows listener_unbound:<name> until it succeeds;
  • a named interface that gains or loses addresses while the server runs is followed: new addresses are bound, vanished ones stop accepting;
  • two listeners whose targets resolve to the same address (an interface and a literal) are rejected before start by prepare.

Connections are TLS only. ALPN offers h2 and http/1.1; a connection that negotiated h2 is served as HTTP/2 only, and every other connection (including one with no ALPN) as HTTP/1.1 only. A client must send its first complete request within the request-head timeout (30 s) of the handshake, or the connection is closed, so an idle or stalled client cannot hold a connection slot. A listener serves at most max_connections connections at a time; further clients wait in the TCP backlog.

Shutdown has two phases. Draining: listeners stop accepting, readiness fails, and every open connection is asked to finish its in-flight requests and close (HTTP/1.1 closes after the current response, HTTP/2 sends GOAWAY). If connections remain when shutdown.grace_secs runs out, force: they are dropped.
