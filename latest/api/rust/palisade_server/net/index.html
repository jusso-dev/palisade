Bind address resolution and network placement checks.

A listener binds either to a literal address or to a named interface (for example an overlay VPN interface such as overlay0). A named interface is resolved to its current addresses when the listener starts, and again on every supervisor tick, so an interface that comes up after the server (a common boot-order race with overlay networks) is picked up without a restart.

The placement check backs deployment.profile = "overlay": under that profile every listener is expected on private, overlay or loopback addresses only, and anything reachable on a public address is reported.

Whether ip is a publicly routable address: not loopback, private (RFC 1918), shared/overlay (RFC 6598 100.64.0.0/10), link-local, unique local (fc00::/7), documentation, benchmarking or otherwise reserved.
reachable_on
The addresses a bound socket address is reachable on. A wildcard (0.0.0.0 or ::) is reachable on every host address of its family (and, for ::, IPv4 too unless the socket is IPv6-only; Palisade always sets IPv6-only).
resolve
The socket addresses target resolves to, given the host’s current addresses. A literal resolves to itself. An interface resolves to each of its addresses; an empty result means the interface is absent or has no address yet.
