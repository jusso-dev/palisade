The most memory a decoded trust list may take: 128 MiB, twice super::MAX_CATALOG_SIZE. What is counted is the size of every value kept (members, their name-value pairs and the catalog-wide ones) and the heap bytes each one owns, as allocated. It is checked as each member and extension is decoded, and before the member list grows, so the overshoot is at most the one member being decoded (itself bounded by the per-member limits).

The per-member limits alone do not bound this: short name-value pairs take a few bytes each in the file but tens of bytes decoded, so a hostile catalog under the size limit could decode to gigabytes before its signature is checked. Real catalogs, whose members carry a digest and a few longer name-value pairs, decode to under twice their size. A catalog over the limit is rejected (CtlError::DecodedTooLarge), so none of its members is indexed.
