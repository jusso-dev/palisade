The NTFS upcase table and the volume’s record of it (#332).

NTFS compares two names by upper-casing each UTF-16 code unit through the volume’s upcase table ($UpCase, MFT record 10), written when the volume is formatted. super::fold_case folds names with the table that Windows 7 and every later version write, and that the OS itself upper-cases with: [palisade_core::upcase].

§Older volumes

A volume formatted by Windows Vista or XP holds an older table, and the OS goes on using it for that volume. Since Windows 8, NTFS records a CRC-64 of the table in the $Info stream of $UpCase, and checks it at mount against the tables it knows. parse_upcase_info reads that CRC from the file record the OS returns (FSCTL_GET_NTFS_FILE_RECORD), and VolumeUpcase::from_crc compares it with STANDARD_UPCASE_CRC, the CRC of this table. Only a volume that records exactly that CRC is known to fold as super::fold_case does. A volume that records another CRC, or none, or whose record cannot be read, is “unknown fold”: path keys on it are refused (see super::NormalizedPath::mark_fold_unknown), so a path rule there is unknown, never matched by a guessed spelling (ADR 0018).

The CRC is the volume’s own claim. A volume prepared elsewhere (a USB disk, a VHD) can claim the standard CRC over a different table, because NTFS compares the stored value, not the table. Path identity is not trusted on such volumes anyway (only fixed local disks qualify), and reading and checking the table itself is #332’s M2 follow-up.

Functions§

parse_upcase_info
The CRC-64 recorded in the resident $Info data stream of a $UpCase file record, as FSCTL_GET_NTFS_FILE_RECORD returns it. Ok(None) if the record has no such stream. Every offset is checked: the bytes come from the file system, which a damaged or crafted volume controls.
upcase_unit
Upper-cases one UTF-16 code unit with the standard NTFS table.
