Mark-of-the-web: parsing the Zone.Identifier alternate data stream.

Browsers, mail clients and archive tools that save a file from the internet attach a Zone.Identifier stream to it. The stream is a small INI file:

[ZoneTransfer]
ZoneId=3
ReferrerUrl=https://example.org/downloads
HostUrl=https://example.org/tool.zip

parse_zone_identifier reads it into a Motw.

§Not a trust signal

Any process that can write a file can also write, change or delete its Zone.Identifier stream, and many tools and file systems drop it (FAT volumes have no streams, and some archive tools do not pass it on). So:

  • a mark says the writer claims the file came from that zone and URL. Policy may use it to treat a file more strictly. It must never make a file more trusted;
  • no mark says nothing: it is not evidence that a file is local.

§Parsing rules

The stream is untrusted input. The parser never fails; it returns what it could read plus MotwWarnings.

  • At most MAX_ZONE_IDENTIFIER_BYTES are read; anything after is ignored and reported. A line the limit cuts is not parsed, because its value may be incomplete (ZoneId=1 of ZoneId=13). At most MAX_MOTW_WARNINGS warnings are kept.
  • UTF-8 (with or without a byte order mark) and UTF-16LE with a byte order mark are accepted. Invalid sequences, and a final odd byte of UTF-16LE, are replaced with U+FFFD and reported.
  • A zone is any run of ASCII digits that fits in a u32, leading zeros included (ZoneId=003 is the internet zone).
  • Section names and keys are compared ignoring ASCII case. Whitespace around keys and values is removed. Lines starting with ; or # are comments. Only keys in the [ZoneTransfer] section count.
  • If a key appears more than once, the first value is used, as the OS’s INI reader does. For ZoneId and AppZoneId the most restrictive value seen is also kept, in Motw::strictest_zone, so a caller that wants to be conservative can use that instead.
