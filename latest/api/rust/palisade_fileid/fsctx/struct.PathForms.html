Expand description

The forms of one file’s path. Only original is always present; each other form needs an OS lookup and is None until one fills it.

Fields§

§original: String

The path as given.

§normalized: Result<NormalizedPath, PathError>

original, normalised. Err if it cannot be (a relative path, a reserved device name and so on).

§nt_path: Option<NormalizedPath>

The NT device form (\Device\HarddiskVolumeN\...).

§dos_path: Option<NormalizedPath>

The drive-letter form (C:\...).

§volume_guid_path: Option<NormalizedPath>

The volume GUID form (\\?\Volume{GUID}\...).

§long_path: Option<NormalizedPath>

The path with every 8.3 short name expanded.

§unc_path: Option<NormalizedPath>

The UNC form, for a mapped drive or a network path.

§dfs_target: Option<NormalizedPath>

The DFS target, for a path in a DFS namespace.

§dfs: Option<DfsOutcome>

What the DFS lookup of the UNC form said. None if none was made. Self::network_key reads it: a timed-out or failed lookup leaves the file without a network key, never with the namespace’s.

§final_path: Option<NormalizedPath>

The final path of the opened handle, with links and junctions resolved. Decisions should use this form (threat model T-agent-13).

pub fn from_original(original: &str) -> Self

The forms that can be worked out without the OS: normalized, and dos_path or unc_path when the path is already in that form and holds no short-name candidate (so it is also long_path).

Source

pub fn from_nt(original: &str) -> Self

As Self::from_original, for an NT object path as the kernel reports image paths (\Device\HarddiskVolume3\...).

Source

pub fn canonical(&self) -> Option<&NormalizedPath>

The form to match rules about the opened file against: the final path of the opened handle. None until a caller has read it.

The other forms describe the name as written. Through a symbolic link, junction or mount point, that name can belong to a different file from the one opened, so there is no fallback to them here (threat model T-agent-13). Use Self::lexical to match the name itself.

Source

pub fn case_folded(&self) -> Option<String>

NormalizedPath::match_key of Self::canonical: the key for link-aware rule matching. None until the final path is known.

Source

pub fn lexical(&self) -> Option<&NormalizedPath>

The name as written, with every short name expanded: the long path. It does not resolve links, so it says what the path names, not which file opening it reaches.

Source

pub fn network_key(&self) -> Option<String>

The key of the file’s network name: the DFS target when known, otherwise the UNC form (for a UNC path, or a mapped drive the OS resolved). A mapped drive, a DFS namespace path and a short-name spelling of one file on a share all give the key of its long UNC path. None for a local file, while a short name is unexpanded, and when a DFS lookup timed out or failed (Self::dfs_unresolved): the UNC form may then be a namespace path whose target is unknown, and its key would not match the target’s rules. A caller treats such a file as unknown, never as matching no network rule.

Source

pub fn dfs_unresolved(&self) -> bool

True if a DFS lookup was made and did not finish (timed out or failed), so the path may be in a namespace whose target is unknown.

Source

pub fn lexical_key(&self) -> Option<String>

NormalizedPath::match_key of Self::lexical, for matching the name rather than the opened file.
