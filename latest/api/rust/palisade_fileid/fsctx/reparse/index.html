Module reparse 

Source
Expand description

Reparse points (#54): what a link, junction, mount point, app execution alias, cloud placeholder or deduplicated file says it is.

The Windows backend reads the reparse data buffer of a file opened without following it (FSCTL_GET_REPARSE_POINT) and hands the bytes to parse_reparse_point. The parser is pure, bounded and fuzzed: the bytes come from the file system, but a standard user can create symbolic links (with developer mode), junctions and app execution aliases in folders they own, so every offset and length is checked and nothing panics.

A reparse point is reported, never followed here. Decisions about a file use the final path of the opened handle (threat model T-agent-13); ReparsePoint says why the name and the file differ. An app execution alias is parsed into its package family name, app user model ID and target executable, so installed-package identity (#53) can use it.
