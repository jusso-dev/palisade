Module fsctx 

Source
Expand description

File-system context (#54): the attributes of a file that come from where and how it is stored, not from its content.

Path rules, owner-based trust, location conditions and download provenance all depend on these. Everything in this module is pure and portable, so it is unit-tested on every OS:

  • path: one canonical form for every way of naming a file (device paths, \\?\, \??\, GLOBALROOT, UNC, trailing dots and spaces, streams, case folding, an 8.3 short-name hook);
  • vars: Palisade path variables such as %WINDIR%;
  • sid: security identifiers;
  • acl: security descriptors, owner classification and the user-writability decision for a file and its ancestor folders;
  • volume: file system, drive and bus types, and the location class;
  • motw: the Zone.Identifier mark-of-the-web;
  • ntfs: the stream list and change-journal records the OS returns;
  • dfs: DFS namespace resolution with a timeout and a cache;
  • meta: file IDs, USNs, timestamps, attributes and hard links;
  • reparse: reparse data buffers (links, junctions, mount points, app execution aliases, cloud placeholders, deduplication);
  • streams: alternate data streams, tagged and sniffed;
  • upcase: which upcase table a volume records, so path keys are refused where names may fold differently (#332);
  • writable: the per-descriptor writability cache, streaming ancestor assessment and enumerate_user_writable_dirs.

The OS reads live in the Windows-only palisade_fileid::win::fsctx module (ADR 0003), compiled only on Windows with the os-trust feature. It reads a file’s final path, its Zone.Identifier stream, owners and security descriptors, writability of real paths, and the OS access check (palisade_fileid::win::access). FsContext keeps every attribute optional, so a caller fills in what it could read and leaves the rest None, and a consumer never mistakes “not read” for “absent”.
