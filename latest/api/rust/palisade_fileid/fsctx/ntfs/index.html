Module ntfs 

Source
Expand description

Parsers for the variable-length records that the Windows file information calls return (#46, #54): the alternate data stream list (FILE_STREAM_INFO) and the file’s change-journal record (USN_RECORD_V2 or USN_RECORD_V3).

The Windows backend (palisade_fileid::win) fills a byte buffer from the OS and hands it here, so the parsing is pure, bounded and tested on every OS. The bytes come from the file system, not from file content, but a filter driver or a damaged volume can still return anything, so every offset and length is checked and nothing panics.

Constants§

MAX_STREAMS
The most streams listed for one file. A file can have far more; the rest are reported as StreamList::truncated.
MAX_STREAM_NAME_UNITS
The longest stream name, in UTF-16 code units, as NTFS allows.
MAX_STREAM_TYPE_UNITS
The longest stream type accepted, in UTF-16 code units. The longest the OS defines is $LOGGED_UTILITY_STREAM (22).
