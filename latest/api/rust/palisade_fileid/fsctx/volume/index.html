Volume and drive classification.

The OS reports a volume’s file system name (GetVolumeInformationW), its drive type (GetDriveTypeW) and the bus of the disk behind it (IOCTL_STORAGE_QUERY_PROPERTY, STORAGE_BUS_TYPE). The functions here turn those raw values into enums, and the enums into a LocationClass that rules and guardrails can condition on. Reading the values needs Windows FFI and is left to the OS backend (#54).

The classification is conservative: when the inputs disagree, the less trusted class wins. A fixed drive on a USB bus is LocationClass::Removable, and a disk on a virtual bus is LocationClass::VirtualDisk unless it is the OS volume. When an input is missing, the result is LocationClass::Unknown, never a trusted class: the OS volume is only LocationClass::OsVolume when it is known not to be hot-pluggable, and another fixed disk is only LocationClass::OtherFixed when its file system, bus and hot-plug state are all known.

The location class and owner support are separate questions. A VHD the OS boots from is LocationClass::OsVolume for location rules, but its owners can still have been written on another machine, so VolumeInfo::supports_owner also requires a known, non-virtual bus.
