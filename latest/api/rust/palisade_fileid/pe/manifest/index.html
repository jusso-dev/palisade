Module manifest 

Source
Expand description

The application manifest (RT_MANIFEST, #45): requested execution level, UI access, auto-elevation, DPI awareness, assembly identity and supported OS GUIDs.

The manifest is untrusted XML. parse_manifest uses quick-xml, a streaming parser that never expands entities defined in a DTD: only the five predefined entities and character references are resolved, and anything else is an error. A document with a <!DOCTYPE> is rejected outright, so no entity definition is ever read. Input size, nesting depth, element count and string lengths are bounded (MAX_MANIFEST_SIZE, MAX_DEPTH, MAX_ELEMENTS, MAX_VALUE_LEN).

Each setting is read only at its place in the manifest schema, by local name (which namespace a name is in is not checked, but every prefix used must be declared, so an undeclared prefix makes the manifest malformed):

SettingPath
requestedExecutionLevelassembly/trustInfo/security/requestedPrivileges/requestedExecutionLevel
assemblyIdentity (the manifest’s own)assembly/assemblyIdentity
supportedOSassembly/compatibility/application/supportedOS
autoElevate, dpiAware, dpiAwarenessassembly/application/windowsSettings/<name>

So a dependency’s assemblyIdentity, or a decoy setting placed anywhere else, is never taken for the real one. The first occurrence at the right place wins, whether it is written <x/> or <x></x>. Element and attribute names are case-sensitive, as in XML; only unprefixed attributes are read, as the manifest schema has no prefixed ones. Values are trimmed, then compared ASCII case-insensitively where the OS does (requireAdministrator, true). Text may be split by references, comments or CDATA sections; it is joined before it is read, and leading whitespace is dropped as it arrives, so padding cannot crowd a value out.

Only XML 1.0 in UTF-8 is read (with at most one byte order mark); XML 1.1 and UTF-16 manifests are errors. The whole document must be well formed: one root element, every element closed, every element and attribute name a valid XML name, every attribute well formed, unique and free of undefined entities, even on elements whose settings are not read.

requires_elevation is the #45 heuristic for whether starting the file will ask for administrator rights.

requires_elevation
Whether starting a file is expected to ask for administrator rights: true if its manifest requests requireAdministrator, or if it has no manifest (or one with an unrecognised execution level) and the installer heuristics match (its file name contains setup, install, update or patch, or its version info mentions installing). A manifest without an execution level is ElevationReason::ManifestWithoutLevel and is not counted. manifest is the parsed process manifest, or None when there is none; a process manifest that is present but cannot be read is decided by super::PeInfo::requires_elevation (ElevationReason::ManifestUnreadable), never passed as None. The OS applies the installer heuristics only to 32-bit images; the caller decides whether that applies.
