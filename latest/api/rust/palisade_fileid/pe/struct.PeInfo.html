Fields§

§file_size: u64

Length of the parsed input, in bytes.

§e_lfanew: u32

e_lfanew: the file offset of the PE signature.

§coff: CoffHeader

The COFF file header.

§optional: OptionalHeader

The optional header.

§data_directories: Vec<DataDirectory>

The data directories present in the optional header (up to 16, in index order). Use PeInfo::data_directory to look one up.

§sections: Vec<Section>

The section headers that were read.

§checksum: Checksum

Stored and computed checksums.

§certificate_table: Option<FileRange>

The certificate table (security directory), if present. Its location is a file offset, always after the headers (the later of SizeOfHeaders and the end of the section table). Parsing it is #48.

§certificate_table_issue: Option<WarningKind>

Why a non-zero security directory entry was not accepted as the certificate table: WarningKind::CertificateTableInvalid, WarningKind::CertificateTableOutOfFile or WarningKind::CertificateTableOverlapsSection. Kept here as well as in PeInfo::parse_warnings, which can be truncated, so the Authenticode image hash can always report it.

§overlay: Option<FileRange>

Bytes after the headers, the last section’s file data and the certificate table, if any.

§debug: DebugInfo

The debug directory.

§resources: Option<ResourceSummary>

A summary of the resource tree, if the image has one.

§version_info: Option<VersionInfo>

The parsed version resource (RT_VERSION), if present.

§imports: Option<ImportInfo>

The import table, if the image has one.

§exports: Option<ExportInfo>

The export table, if the image has one.

§manifest: Option<Manifest>

The application manifest: the lowest standard RT_MANIFEST ID present (1, 2 or 3), parsed. None when there is none, or when it cannot be read or does not parse (with a warning); a higher ID is never used in its place. An ID counts as present when its directory entry exists, even if no data under it can be read.

§manifest_id: Option<u16>

The RT_MANIFEST ID Self::manifest was read from: 1 is the process manifest the OS reads at process creation (and so the one that decides elevation); 2 and 3 are DLL isolation manifests. Set even when Self::manifest is None because that manifest could not be read or parsed, and set to the lower ID when the resource tree is too damaged to rule it out, so a higher ID never stands in.

§driver: DriverClass

Kernel driver signals and the verdict.

§parse_warnings: Vec<ParseWarning>

Non-fatal problems, at most MAX_WARNINGS.

§parse_warnings_truncated: bool

More than MAX_WARNINGS warnings occurred; the rest were dropped.

Source

pub fn requires_elevation(&self, file_name: Option<&str>) -> Elevation

The #45 elevation heuristic, for a file named file_name (the final path component, if known), from the process manifest (ID 1) only. See manifest::requires_elevation. A process manifest that is present but cannot be read or parsed is ElevationReason::ManifestUnreadable and counts as requiring elevation.

Source

pub fn section_for_rva(&self, rva: u32) -> Option<&Section>

The section whose mapped range contains rva: VirtualAddress up to VirtualSize (or SizeOfRawData when VirtualSize is zero) rounded up to SectionAlignment, as the loader maps it.

Source

pub fn rva_to_offset(&self, rva: u32, len: u32) -> Option<u64>

Maps the RVA range rva..rva + len to a file offset, as the loader would. The range must lie in the file-backed part of one section, or in the headers; zero-filled memory has no file offset.
