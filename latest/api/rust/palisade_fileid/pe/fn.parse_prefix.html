pub fn parse_prefix(prefix: &[u8], file_len: u64) -> Result<PeInfo, PeError>
Expand description

Parses the headers of a PE image from prefix, the first bytes of a file that is file_len bytes long, so a large file can be identified while it is read in one sequential pass.

The result has the headers, data directories, section table, certificate table location and overlay, which is everything the Authenticode image hash and the page hash tables need. Everything that depends on the file’s length (the certificate table checks, PeInfo::overlay, PeInfo::file_size and the SectionDataOutOfFile warnings) uses file_len. The DOS, COFF and optional headers and the section table (up to MAX_SECTIONS entries) must be inside prefix when the file is long enough to hold them; otherwise the result would describe fewer sections than the file has, so it is PeErrorKind::PrefixTooShort.

When prefix is shorter than the file, the debug directory, the resource tree, the version info, the manifest, and the import and export tables are not parsed (they are left empty, with no warning), because they can lie anywhere in the file. The driver verdict needs the imports, so it is left at its default (DriverClass::default) too. Neither the checksum nor section entropy is computed (ParseOptions::metadata_only). When prefix holds the whole file the result is that of parse_with with ParseOptions::metadata_only.

prefix longer than file_len is cut to file_len.
