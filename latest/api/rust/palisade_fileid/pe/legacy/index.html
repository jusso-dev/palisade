Identity of 16-bit NE and 32-bit LE / LX executables (#45).

These older MZ formats have no version resource that the OS reads, but they name themselves. parse reads:

  • the module name, the first entry of the resident name table;
  • the module description, the first entry of the non-resident name table;
  • the format and target operating system, which are the minimal identity returned when the names cannot be read.

Each name table entry is a length byte, then that many bytes of single-byte text, then an ordinal. A length byte of zero ends the table, so an empty table means the name is absent.

The input is untrusted, and the parser fails conservative:

  • Every read is bounds-checked, and all offset arithmetic is checked. A name is at most 255 bytes, because its length is one byte, so nothing is allocated from a size the file declares.
  • A name is reported only if it lies wholly inside the file and, where the header gives the table’s length, inside the table. Otherwise it is absent, with a LegacyWarning.
  • The text is in a code page that the file does not name. Printable ASCII is kept as it is. Any other byte becomes U+FFFD and LegacyName::non_ascii is set, so a rule can never match a guessed decoding. The exact bytes are kept in LegacyName::raw.
  • An LE or LX header that declares big-endian byte or word order is identified, but its names are not read.

parse fails with a LegacyError only when the file is not one of these formats.
