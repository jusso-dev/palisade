A parsed OCSP response. Its signature is checked only when it is used against an issuer (Self::verified_by).

pub fn verified_by(&self, issuer: &CertSummary) -> bool

Whether issuer, or a responder issuer delegated to, signed the response (see Self::answers_for for the rules). This alone does not say the response is about a certificate issuer issued, and it checks no revocation of the responder; Self::answers_for and revocation do both.

Source

pub fn max_checks(&self) -> usize

The most signature verifications checking a response can make: one for the issuer, and two (the responder’s certificate, then the response) for each certificate the response carries.

Source

pub fn answers_for<'a>( &'a self, cert: &'a CertSummary, issuer: &'a CertSummary, now: i64, ) -> Vec<&'a SingleResponse>

The answers this response gives about cert, issued by issuer, at time now: the SingleResponses whose CertID names cert under issuer, and only if issuer signed the response, or a delegated responder did. Such a responder must be named by the responder ID; name issuer as its issuer (by DER name and key identifier) with a signature that verifies with issuer’s key; list the OCSP Signing EKU, allow digitalSignature if its key usage is restricted, and carry no unprocessed critical extension; and have been valid when the response was produced. A good answer from a delegated responder that has expired by now is left out: it can no longer vouch, and so is one before the responder became valid. Empty otherwise. This checks no revocation data: super::RevocationSet also rejects a responder that its offline entries, the issuer’s CRLs or the issuer’s own OCSP answers revoke.

pub fn responses_for<'a>( &'a self, cert: &'a CertSummary, issuer: &'a CertSummary, ) -> impl Iterator<Item = &'a SingleResponse> + 'a

The SingleResponses for cert, issued by issuer, in order, whoever signed the response.
