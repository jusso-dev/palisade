Expand description

The chains of one signer certificate.

Fields§

§certificates: Vec<ChainCert>

Every certificate referred to: the signer first, then the other embedded certificates that parsed, in blob order (duplicates dropped), then any policy certificates a path or issue uses.

§leaf: usize

The signer certificate.

§as_provided: ChainPath

The as-provided chain: embedded certificates only, leaf first.

§as_provided_alternatives: Vec<ChainPath>

Other as-provided paths (cross-signed alternatives), best first.

§intermediates: Vec<usize>

The embedded certificates of the full chain between the leaf and the root, lowest first: the full chain’s embedded prefix, without the leaf and without a self-signed root.

§pca: Option<usize>

The “PCA”: the highest certificate provided in the file on the full chain, excluding the root. None when the file carries no intermediate on it (only the leaf, or the leaf and a root), in which case Publisher-level OS rules cannot be made for it.

§root_as_provided: Option<usize>

The self-signed root of the full chain, if the file carries it. For a self-signed leaf, the leaf itself.

§full_chain: ChainPath

The chosen full chain, built over the embedded certificates and the TrustConfig.

§alternatives: Vec<ChainPath>

Other full paths, best first. When the full chain is anchored, only other anchored paths.

§chain_complete: bool

The full chain ends at a self-signed certificate or a trust anchor.

§anchored_to: Option<AnchorRef>

The anchor the full chain reaches.

§anchor_source: AnchorSource

Where that anchor came from.

§well_known_root_id: Option<u8>

The well-known ID of the full chain’s root (its self-signed top or anchor), from TrustConfig’s table.

§basic_constraints_ignored: Vec<usize>

The issuers on the full chain that issued their child only because TrustConfig::ignore_basic_constraints relaxed their basic constraints: indices into Self::certificates, lowest first. Empty when no relaxation was needed.

§time_nesting_violations: Vec<usize>

The certificates on the full chain whose validity period is not inside their issuer’s (“not time nested”): indices into Self::certificates, lowest first. This is reported, not judged: whether it fails a signature is policy’s call (#50, ValidityPolicy::require_time_nesting), as the OS ignores it for code signing by default.

§issues: Vec<ChainIssue>

What was found along the way.

pub fn chain_has_eku(&self, eku: &ObjectId) -> bool

Whether eku is in force for the whole full chain: the leaf lists it, and no certificate above restricts it away (each has no extKeyUsage, or lists eku or anyExtendedKeyUsage). This is how the OS treats EKUs on issuers.

Source

pub fn permits_code_signing(&self) -> bool

Whether the full chain may sign code: every certificate permits the Code Signing EKU (has no extKeyUsage, or lists Code Signing or anyExtendedKeyUsage).

Source

pub fn meets_min_key_bits(&self, min_rsa_bits: u32, min_ec_bits: u32) -> bool

Whether every key in the full chain is at least min_rsa_bits (RSA) or min_ec_bits (elliptic curve) long. Any other key algorithm fails.

Source

pub fn cert_sig_algs_allowed(&self, allowed: &[SignatureAlgorithm]) -> bool

Whether every certificate signature in the full chain uses an algorithm in allowed. The signature of a self-signed certificate, and of the anchor at the top of an anchored chain, is not counted: nothing relies on it.
