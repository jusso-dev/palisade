Expand description

One way an image’s layout departs from the Authenticode specification.

Variants (Non-exhaustive)§

This enum is marked as non-exhaustive
Non-exhaustive enums could have additional variants added in future. Therefore, when matching against variants of non-exhaustive enums, an extra wildcard arm must be added to account for any future variants.
§

NoSecurityDirectoryEntry

The optional header has no certificate table entry (NumberOfRvaAndSizes is below 5, or the header is too small). The bytes where it would be are hashed like any others.

§

SectionTableIncomplete

Fewer section headers were read than NumberOfSections declares (the table is cut off, or over pe::MAX_SECTIONS), so the layout could not be checked in full.

Fields

§declared: u16

NumberOfSections.

§parsed: u16

Section headers read.

§

SizeOfHeadersTooSmall

SizeOfHeaders ends before the section table does, so the specification’s header step would leave part of the table out.

Fields

§size_of_headers: u32

SizeOfHeaders.

§headers_end: u64

File offset where the section table ends.

§

HeadersOutOfFile

SizeOfHeaders is larger than the file.

Fields

§size_of_headers: u32

SizeOfHeaders.

§

SectionNotContiguous

Taken in PointerToRawData order, a section’s raw data does not start where the headers or the previous section end: there is a gap (pointer_to_raw_data > expected) or an overlap (<). Only the first such section is reported.

Fields

§index: u16

Index of the section in the section table.

§expected: u64

Where its data should start.

§pointer_to_raw_data: u32

Its PointerToRawData.

§

SectionOutOfFile

A section’s raw data runs past the end of the file.

Fields

§index: u16

Index of the section in the section table.

§

CertificateTableRejected

The certificate table entry is non-zero but the parser did not accept it as a certificate table (it points into the headers, runs past the end of the file or overlaps a section). Nothing is excluded for it.

Fields

§offset: u32

The entry’s file offset field.

§size: u32

The entry’s size field.

§reason: Option<WarningKind>

The parser’s reason (PeInfo::certificate_table_issue).

§

CertificateTableInsideSectionData

The certificate table starts before the end of the section data as the specification reads it (PointerToRawData + SizeOfRawData of the last section). This happens when a section’s pointer is not sector-aligned: the loader, and so the parser, rounds it down, but the specification’s steps use it as written.

Fields

§offset: u64

The table’s file offset.

§sections_end: u64

Where the section data ends.

§

CertificateTableMisaligned

The certificate table does not start on an 8-byte boundary.

Fields

§offset: u64

Its file offset.

§

DataAfterCertificateTable

Data follows the certificate table. It is hashed, but a signer never covered it, so a signature’s digest will not match.

Fields

§offset: u64

File offset where the extra data starts.

§size: u64

Its size in bytes.
