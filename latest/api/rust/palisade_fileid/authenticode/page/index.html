Authenticode page hashes (#47).

A signer can put a table of page hashes in an Authenticode signature (an SpcSerializedObject in the signed SpcPeImageData: version 1 for SHA-1, version 2 for SHA-256). The OS can then check each page of the file as it maps it, instead of hashing the whole image first. This module builds that table from a file, checks a signed table against a file, and gives the single “page hash” value OS policy hash rules use.

§How the table is built

Pages are 4 KiB (PAGE_SIZE). Each entry is a page’s file offset (a little-endian u32) and the digest of its bytes, zero-padded to 4 KiB:

  1. The header page, at offset 0: the bytes from 0 to SizeOfHeaders, minus the CheckSum field and the certificate table entry (the two header fields the image hash leaves out too), then zeros up to 4 KiB. The 12 excluded bytes are dropped, not zeroed, so 4,084 bytes are hashed.
  2. Section pages: for each section with raw data, in section table order (which must also be file order), one entry every 4 KiB from PointerToRawData to PointerToRawData + SizeOfRawData. A section’s last page stops at its end and is zero-padded.
  3. A final entry at the end of the last section’s data (or at SizeOfHeaders when no section has raw data), with an all-zero digest.

The tests check this against page hash tables that an open-source signer made over synthetic images (tests/fixtures/page_hash).

§When there is no table

A page table says where each page’s bytes are, so it is only built for an image whose layout conforms to the Authenticode specification (see super::hash) and whose headers fit in one page. Anything else is a PageHashError, never a best-effort table: a guessed table would make rules that silently never match.

§Checking a signed table

verify_page_hashes compares a signature’s table with the file and reports the first entry that does not match. A signed table is only as trustworthy as the signature that carries it, so verify_signature_page_hashes checks only tables from signatures that verify cryptographically. That includes signatures whose image digest no longer matches the file: the page check then names the first page that changed.

§The code integrity “page hash” rule value

For each file, OS policy tooling emits two single-value “page hash” rules (SHA-1 and SHA-256) next to the two Authenticode hash rules. By the current documentation the value is the digest of the file’s first page as code integrity lays it out: the header page above. PageHashTables::page_sha1 and PageHashTables::page_sha256 return it. Like the Authenticode digest it is the same for user-mode and kernel-mode rules (super::HashScenario).

The construction is not fully documented, so it is checked against the OS tooling itself: on Windows, tests/os_policy_tooling.rs runs the OS policy cmdlets over synthetic images through the committed script tests/fixtures/page_hash/os-policy-hashes.ps1, and compares every Authenticode and page hash rule they emit with this crate’s values. CI runs it on its Windows runners.

§Memory

A table holds 24 (SHA-1) or 36 (SHA-256) bytes per 4 KiB page of section data, under 1% of the image size.
