Fields§

§classifier_version: u16

CLASSIFIER_VERSION at the time of classification.

§content_kind: FileKind

What the content is.

§extension_kind: ExtensionKind

What the extension claims.

§extension: Option<String>

The lowercased extension, if the name has one.

§mismatch: bool

Content and name disagree (mismatch_severity is not None).

§mismatch_severity: MismatchSeverity

How serious the disagreement is.

§confidence: Confidence

How sure the classifier is of content_kind.

§heuristic: bool

content_kind rests on a heuristic rather than a defined magic or structure: a DOS .com file, or a script found by keywords or by its extension.

§extension_assisted: bool

The extension decided content_kind where content alone could not: a script language, .com, .msm, .appx, .scr, .hta with HTML content, or .pyc.

§pe: Option<PeDetails>

PE details, for FileKind::Pe.

§text_encoding: Option<TextEncoding>

The text encoding, for text and script content.

§flags: ContentFlags

Informational flags.

§file_size: u64

The file length.

§parse_error: Option<ParseError>

Why part of the file could not be read or parsed, if it could not.

pub const fn is_executable_content(&self) -> bool

Whether the content can run code; see FileKind::is_executable_content. It is also true for a FileKind::Zip with a parse_error: its structure was ambiguous, broken or too large to read in full, so it may be an app package, Java archive or zip application that some ZIP reader runs, and it fails closed.
