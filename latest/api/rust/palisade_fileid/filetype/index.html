Content-based file type detection (#44).

classify decides what a file is from its bytes (magic numbers and structure), never from its name alone. The name, when given, is used only to report what the extension claims (ExtensionKind), to flag a mismatch between the two, and as a tie-breaker in the few places the format has no magic (DOS .com files, and text that could be any of several script languages).

The input is untrusted:

  • The classifier reads the first HEAD_LEN bytes, then makes a few targeted reads whose total is capped at MAX_TARGETED_READ. It never loads the whole file.
  • No input can make it panic. Every read is bounds-checked, all offset arithmetic is checked, and every loop over file data has a fixed limit.
  • It never fails. A file it cannot make sense of is FileKind::Unknown; a file whose magic is recognised but whose structures are broken keeps the outer kind. Either way the reason is in Classification::parse_error.

Every result carries CLASSIFIER_VERSION, so results cached by a later stage can be invalidated when the heuristics change.
