The unified file identity record (#55).

identify and identify_bytes run the other modules of this crate over one file and fold their outputs into one FileIdentity:

Which reader runs is decided by the content the classifier saw, never by the name alone: a PE image named .ps1 or .msix is judged only as a PE, so no script or package signature can vouch for it. Groups other issues still deliver are present in the schema now, so the record’s shape does not change when they land, and hold Field::NotYetSupported with the issue numbers: the owner, writability, streams, reparse points, file ID, volume and provenance in fs (#54).

§Signing state

The record folds embedded signatures and catalogs into one verdict, SigningStateKind. It is trusted only when a trusted signer vouches for the file: an embedded signature that passed every #48, #49 and #50 check, or a catalog whose signer is trusted and whose match does not rely on SHA-1 (ADR 0008). It is unsigned only when the file has no embedded signature and a catalog lookup found nothing. A script, an installer and an app package are judged by their own signatures with the same trust and validity evaluation as a PE image’s; a package whose manifest names another publisher than its signer, a script or package changed after signing, and a container the strict reader refuses are invalid. A file whose format’s signatures are not read (a cabinet, an encoded script, a file over a reader’s limit), or that was not looked up in any catalog, is unverified, never unsigned. So is a script or installer that no catalog lists: which digest catalogs made by OS tooling list them under is not yet checked (#51), so a miss proves nothing.

§Fail-conservative

Nothing in the record is guessed. A tier that fails leaves its fields Field::Unavailable and an entry in FileIdentity::errors; it never turns into “unsigned”, “not a driver” or “clean”. A masquerade check that could not run is listed in Masquerade::unassessed. A path counts as user-writable until #54 reads its ACLs.

§Serialised form and evolution

FileIdentity serialises with serde: snake_case field and variant names, digests as lowercase hex, times as seconds since the Unix epoch. Each Field is {"status": "computed", "value": ...} or a status without a value (not_requested, not_applicable, unavailable with a reason, not_yet_supported with the issue numbers). The schema is fileid.v1 (SCHEMA_VERSION). Within fileid.v1:

  • fields and enum variants are only ever added, never renamed, removed or given a new meaning;
  • a consumer must ignore fields and variants it does not know;
  • a breaking change is a new schema version, fileid.v2.

The protobuf form for the agent-server protocol is palisade-proto’s (#55, follow-up), with the same field names; protobuf field numbers, once assigned, are never reused or renumbered.
