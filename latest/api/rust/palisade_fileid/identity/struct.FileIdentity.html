Fields§

§schema: &'static str

Always SCHEMA_VERSION.

§library_version: &'static str

The version of palisade-fileid that made the record.

§path: Option<String>

The path given to super::identify. None for super::identify_bytes.

§name_hint: Option<String>

The name hint given to super::identify_bytes: untrusted, as the uploader claimed it.

§requested_tiers: Tiers

The tiers the caller asked for.

§computed_tiers: Tiers

The tiers whose attributes were computed. A requested tier is missing here when it failed, or when nothing in it applies to the file yet (the deep tier of a PE image, until content tags run).

§name: NameInfo

The file name, from the path or the name hint. Needs no I/O.

§size: Field<u64>

The size in bytes (stat tier).

§content_sha256: Option<String>

The SHA-256 of the bytes the content tiers read, hex: set whenever a tier read the whole file (classify, hash or trust), so two records can be shown to describe the same content before they are merged. None when no tier read it.

§timestamps: Field<Timestamps>

File system times (stat tier).

§kind: Field<KindSummary>

The content-based file kind (#44, classify tier).

§pe: Field<PeSummary>

PE headers and version information (classify tier).

§hashes: Field<Hashes>

Flat, Authenticode and page hashes (hash tier).

§signing_state: Field<SigningState>

The file’s signing state, embedded and catalog signatures together (trust tier).

§signatures: Field<Vec<SignatureSummary>>

Every embedded signature with its chain (trust tier).

§catalog_matches: Field<Vec<CatalogMatchSummary>>

Every catalog that lists the file (trust tier).

§installer: Field<InstallerSummary>

Windows Installer identity (#53, deep tier).

§package: Field<PackageSummary>

Packaged-app identity (#53, deep tier).

§script: Field<ScriptSummary>

Script signature and identity (#52, deep tier).

§content_tags: Field<ContentTagsSummary>

Content tags (#44, deep tier): installer engines, self-extracting archives, embedded executables and the organisation’s patterns. Descriptive only: no verdict reads them.

§os_cross_check: Field<OsCrossCheckSummary>

The OS trust-verification API’s verdict on the embedded signatures, compared with this record’s (#48, trust tier). Diagnostic only (ADR 0018): nothing in this library reads it to change a verdict.

§fs: FsInfo

File system context (stat and context tiers).

§derived: Derived

Attributes worked out from the groups above.

§masquerade: Masquerade

The renamed and masquerading binary assessment.

§strengths: Vec<AttributeStrength>

How strong each attribute is as a rule identity.

§errors: Vec<IdentityError>

What went wrong, per tier.

pub fn merge(&mut self, other: Self, ctx: &IdentityContext<'_>) -> bool

Folds other, a record of the same file computed for other tiers, into this one: the agent computes T0 to T3 at execution and T4 and T5 later. A field takes other’s value when it says more (a value beats a reason, a reason beats “not requested”). The derived attributes, masquerade assessment and strengths are recomputed with ctx.

Returns false, and changes nothing, when the records are shown to describe different files or versions: a different path or name hint, a different final path, file ID or change journal stamp, size, last-write or creation time, or a different content digest; and when both records hold attributes derived from the content, unless both carry the same content digest. Otherwise an attribute only one record has is not compared.

The file ID and change journal stamp are read by the context tier only, so they are compared only between two records that both ran it. What joins an execution-time record (T0 to T3) to a later one (T4 and T5) is the content digest: the deep tier reads the content too, so both carry one and must agree. A later record of the context tier alone carries no digest, and is joined on the path, final path, size and times; a file rewritten in place with the same size and restored times is not detected then.
