palisade_fileid::identity

Module strength 

Source
Expand description

How strong each attribute of a FileIdentity is as a rule identity.

Rule tooling (policy lint, the guardrails on generated rules) must know which attributes an attacker can change. The classes, from the issue (#55) and ADR 0008:

ClassAttributes
Strongflat SHA-256 (and SHA-384, SHA-512); Authenticode SHA-256 of a conformant image; the chain identity (thumbprints, TBS hashes) of a trusted signer
Mediuma trusted publisher, alone or with product, file name and version; OriginalFilename under a trusted signature; the SHA-256 page hash value; the normalised MSI hash; the package family name of a package whose valid signature a trusted signer made; a path that is not user-writable
WeakCompanyName, ProductName, FileDescription and InternalName; OriginalFilename on a file no trusted signer covers; an untrusted signer; the file name; the normalised script hash; the package family name of a package no trusted signer binds; an installer’s product and upgrade codes and Manufacturer; a user-writable path, or one whose writability is unknown
InsecureSHA-1 and MD5 digests of any kind; the digest of an empty file; the Authenticode digest of a non-conformant image; a catalog match that relies on SHA-1

An attribute that is not in the record has no entry.
