Packaged apps (#53): .msix/.appx packages and .msixbundle/ .appxbundle bundles.

parse_package reads a package or bundle from memory and returns a PackageIdentity: the manifest identity, the publisher ID, package family name and package full name, the display names, applications, capabilities, extensions and dependencies, for a bundle its member packages, and the package signature checked against the package.

§Layers

  • zip: a strict ZIP reader that accepts only the shape packaging tools write and refuses anything ZIP readers disagree about.
  • xml: a bounded, namespace-aware XML tree with no DTD support.
  • manifest, blockmap, identity: the package formats.
  • this module: the signature and the identity record.

§The signature

AppxSignature.p7x is the bytes PKCX followed by an Authenticode SignedData. Its indirect data is SPC_SIPINFO naming the package subject type (0AC5DF4B-CE07-4DE2-B76E-23C839A09FD1 for a package, 0F5F58B3-AADE-4B9A-A434-95742D92ECEB for a bundle), and its digest is not one hash but a tagged list (signed_digest):

  • APPX, then
  • AXPC and the hash of every local file record (header, data, data descriptor) except the signature’s, in archive order;
  • AXCD and the hash of the central directory without the signature’s entry, followed by end records rewritten for that shorter directory (its entry count, size and offset, with the disk fields zero);
  • AXCT and the hash of [Content_Types].xml, uncompressed;
  • AXBM and the hash of AppxBlockMap.xml, uncompressed;
  • AXCI and the hash of AppxMetadata/CodeIntegrity.cat, if present.

All under the block map’s hash method. The archive must have ZIP64 end records: the OS signing tool always writes them, and the OS rejects a signature on a classic archive whatever its digest (PackageSignatureIssue::NotZip64). The signature also must be the last local record and the last central directory entry, so nothing unsigned can sit after it.

SignatureKind::Package signatures go through the same SignedData decoder, signer certificate lookup, messageDigest and signature checks as PE signatures, nested signatures included. A signature is valid only when, in addition, the block map verifies against every file (blockmap::verify) and the subject DN of the signer of every valid signature, nested ones included, rendered as the OS renders it, equals Identity@Publisher exactly; a different publisher is PackageSignatureIssue::PublisherMismatch. Special parts (AppxSignature.p7x, the manifests, the block map) are found by part name: percent-decoded and ASCII case-insensitive, as OPC compares them. The report then feeds crate::authenticode::evaluate_trust and crate::authenticode::evaluate_validity unchanged.

§Fail conservative

Any archive this reader refuses is an error, never an unsigned package. Anything wrong with the signature, the block map or the publisher demotes every signature so that none is valid. Bundles are identified by their bundle manifest; their member packages are listed, not parsed or verified one by one. A bundle’s block map lists only the bundle manifest; each payload package must be a stored member at the offset and of the size the bundle manifest gives (blockmap::verify_bundle), and the signature covers its bytes through the local records (AXPC).
