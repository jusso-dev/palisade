Module blockmap 

Source
Expand description

AppxBlockMap.xml: the per-file block hashes every package carries, and their check against the archive.

The block map lists every file of the package (except the signature, the block map itself, [Content_Types].xml and the code integrity catalog) with its uncompressed size, the size of its local file header and the hash of each 64 KiB block of its uncompressed content, under the map’s HashMethod. The signature signs the block map’s hash, so the map is what ties every file’s content to the signature.

A bundle’s block map lists only its bundle manifest; verify_bundle checks its payload packages against the bundle manifest instead (the signature still covers their bytes, through the local records).

verify checks the map against an Archive and fails closed: a file the archive has but the map does not list (or the reverse), a name listed twice, a size, local-header size or compressed size that does not match, a deflated file whose blocks do not all give their compressed size, a block count that does not fit the size, or any block whose hash differs is a mismatch.

verify_bundle
Checks a bundle’s map against archive. A bundle’s block map lists its bundle manifest and nothing else: the payload packages are not in it. Each payload must instead be listed in payloads (the bundle manifest) exactly once, and be a stored member (the OS packaging tool never compresses one) whose data starts at the manifest’s Offset and has its Size, so no member escapes both. Their bytes are covered by the signature through the local records. A payload that is not in the archive (a flat bundle’s) is a mismatch.
