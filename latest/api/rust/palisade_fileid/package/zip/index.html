palisade_fileid::package

Module zip 

Source
Expand description

A strict, bounded ZIP reader for app packages (OPC containers).

App packages are ZIP files written by packaging tools in one predictable shape, so this reader accepts only that shape and rejects everything ZIP readers disagree about. A package that reads here reads the same in every reader, so its signature and identity cannot depend on which reader looked at it:

  • exactly one end-of-central-directory record, found at the very end (an archive comment is not allowed), and, when the archive needs ZIP64, exactly one ZIP64 locator and record right before it, with counts, sizes and offsets that agree with the classic record;
  • one disk only (with ZIP64, the classic record’s two disk numbers may both be the 0xffff marker, as the OS packaging tool writes them; the ZIP64 record’s must still be 0);
  • the central directory runs from its stated offset to the ZIP64 record or the end record, with no gap and nothing after it;
  • local entries tile the file from offset 0 to the central directory in central-directory order: each local header, its data and its data descriptor end where the next local header starts;
  • a data descriptor’s sizes are 8 bytes when the entry’s local header gives ZIP version 4.5 or later, and 4 bytes otherwise (the OS packaging tool writes 4.5 and 8-byte sizes; the OS signing tool, rewriting an archive, writes 2.0 and 4-byte sizes, in ZIP64 archives too); an entry with a ZIP64 extra field must give 4.5;
  • each local header agrees with its central entry (name, method, flags, CRC and sizes, or zero for those three when a data descriptor follows, which must carry its signature and whose values must then agree);
  • a central entry’s extra data, if any, is exactly one ZIP64 block with exactly the fields its 0xffffffff markers call for (the package digest writes entries that way, so anything else would be read differently from how it is signed);
  • names, and their percent-decoded OPC part names, are valid UTF-8, not empty, without \, a leading /, empty, . or .. segments, or NUL; and part names are unique compared ASCII-case-insensitively, as OPC compares them, so two spellings of one part are a duplicate;
  • extra data, in a local header or a central entry, is either empty or exactly one ZIP64 block with exactly the fields its 0xffffffff markers call for (none with a data descriptor);
  • method 0 (stored, sizes equal) or 8 (deflate); no encryption, no patch data, no strong encryption flags;
  • every member’s data inflates to exactly its declared size and CRC: checked when it is read (Archive::read, Archive::stream), not when the archive is opened, so opening an archive does not vouch for members nobody reads (the package signature check reads them all).

Member reads are bounded by MAX_MEMBER_SIZE, and the whole archive by MAX_ENTRIES. Inflation is streamed in fixed chunks with a size cap, so a small member cannot claim gigabytes.
