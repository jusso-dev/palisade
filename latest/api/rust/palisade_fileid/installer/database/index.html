The Windows Installer database inside a compound file: stream names, the string pool and the tables.

§Stream names

Table and stream names are stored compressed: each pair of characters from [0-9A-Za-z._] becomes one code unit in U+3800..U+47FF, a single such character one code unit in U+4800..U+483F, and a table’s stream name starts with U+4840. decode_stream_name reverses that, so the Property table is the root stream decoded as "\u{4840}Property" and the binary stream Binary.Icon is decoded as "Binary.Icon".

§String pool

_StringPool holds a header (the codepage, and bit 31 for 3-byte string references), then one (length, refcount) pair of 16-bit values per string. _StringData holds the strings back to back. A string of 64 KiB or more takes two pairs: a zero length whose refcount is the high word, then the low word. String 0 is the null string.

§Tables

_Tables lists the table names and _Columns each table’s columns (table, number, name, type). A table stream holds its rows column by column: every row’s first column, then every row’s second column, and so on. Integers are stored with the sign bit flipped, so 0 is null; strings are references into the pool (2 or 3 bytes), binary columns 2 bytes.

Anything inconsistent (a pool that does not cover _StringData, a table stream that is not a whole number of rows, a reference past the pool) is an error for that table, never a guess.

Streams are looked up the way the installer opens them: by their encoded name, compared case-insensitively. A stream whose name merely decodes to the same text (an unencoded \u{4840}Property, say) is a different stream the installer never reads, so it is never read here either.
