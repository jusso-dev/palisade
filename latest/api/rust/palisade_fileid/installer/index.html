Source
Expand description

Windows Installer packages (#53): .msi databases, .msp patches, .mst transforms and .msm merge modules.

parse_installer reads a package from memory and returns an InstallerIdentity: what kind of package it is, the product identity from the Property table and the summary information, the patch or transform targets, an inventory of embedded executable content, the package’s Authenticode signature, checked against its content, and a normalised SHA-256 that stays the same across copies of a package whose only differences are timestamps.

§Layers

  • cfb: a bounded compound-file reader. Every sector belongs to at most one chain, every directory entry is reached at most once, and any inconsistency is an error.
  • database: stream-name decoding, the string pool and the tables.
  • summary: the summary information property set.
  • this module: identity, signature and hashes.

§Package kind

The root storage’s CLSID says what a package is: 000C1084-0000-0000-C000-000000000046 for an installer database (an .msi, or an .msm when it has a ModuleSignature table), 000C1086-… for a patch and 000C1082-… for a transform. A file whose root has any other CLSID is InstallerError::NotInstaller.

§The signature

An installer package is signed by an Authenticode SignedData in the root stream \u{5}DigitalSignature. Its indirect data is SPC_SIPINFO (1.3.6.1.4.1.311.2.1.30) naming the installer subject type, 000C10F1-0000-0000-C000-000000000046, and its digest is the content hash, computed like this (content_digests):

  1. Start at the root storage.
  2. Sort the storage’s children by name: compare the UTF-16LE bytes of the names up to the shorter length; when one is a prefix of the other, the longer name sorts first.
  3. For each child in that order: in the root, skip the \u{5}DigitalSignature stream, and hash the content of the \u{5}MsiDigitalSignatureEx stream only through step 5; hash a stream’s bytes; recurse into a storage (a storage with one of those names included).
  4. After the children, hash the storage’s 16-byte CLSID.
  5. When the package has \u{5}MsiDigitalSignatureEx, the hash includes that stream’s bytes at its sorted place, and the stream must equal the metadata hash: the same walk over names, sizes, CLSIDs, state bits and times instead of content (see metadata_digest).

SignatureKind::Msi signatures go through the same SignedData decoder, signer certificate lookup, messageDigest and signature checks as PE signatures, nested signatures included. Their report then feeds crate::authenticode::evaluate_trust and crate::authenticode::evaluate_validity unchanged.

§Fail conservative

A package is reported signed only when its container parses without any inconsistency. A compound file this reader rejects is an error, not an unsigned package. A signature stream that does not decode is SignatureStatus::Malformed; an MsiDigitalSignatureEx that does not match is a digest mismatch; a content hash that does not match is SignatureStatus::DigestMismatch. None of those is ever valid.

§The normalised hash

InstallerIdentity::normalised_sha256 is a Palisade-specific identity, not one the OS computes. It is SHA-256 over:

  1. the ASCII bytes palisade-msi-normalised-v1\0;
  2. the root CLSID (16 bytes);
  3. for every stream except \u{5}DigitalSignature, \u{5}MsiDigitalSignatureEx and \u{5}SummaryInformation (and \u{5}DocumentSummaryInformation), in the order of a depth-first walk that visits each storage’s children sorted by their UTF-16 names (code unit order): the path (storage names and the stream name, each UTF-16LE, joined by U+002F), as a u32 LE byte length and the bytes; then the content, as a u64 LE length and the bytes; storages add their path and CLSID the same way, tagged S where streams are tagged F;
  4. the summary information without its four FILETIME properties (edit time, last printed, created, last saved), in the canonical encoding of summary::canonical_without_times, tagged I and preceded by its u64 LE length; or, if the stream is present but cannot be parsed, its raw bytes, tagged R the same way; or the tag N if the package has none.

Names compare case-insensitively when deciding what to leave out, as the format compares them, and only streams with those names are left out: a storage with one of them is hashed like any other. Path components are never empty and cannot contain /, which the compound file reader rejects in names, so a path has one reading.

Directory-entry times, the signature streams and sector layout never enter it, so two copies of a package that differ only in when they were built, saved or signed hash the same. It is identity of medium strength (NormalisedHashStrength::Medium): it ignores bytes that the flat hash covers, and it is not a signature.

§Limits

MAX_INSTALLER_SIZE, MAX_SIGNATURE_SIZE, MAX_SUMMARY_SIZE, the CFB limits (cfb::MAX_DIRECTORY_ENTRIES, cfb::MAX_STORAGE_DEPTH) and the table limits (database::MAX_STRINGS, database::MAX_TABLES, database::MAX_TABLE_ROWS; row limits are checked from a table’s stream size before its rows are allocated) bound the work and memory any input can cause. The fuzz_msi_tables target fuzzes the whole path.
