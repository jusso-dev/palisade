Expand description

Opens files and reads their FileKey; implemented by the OS backend (#54).

Everything is done through one opened handle. The key read before hashing, the bytes hashed and the key read after hashing must all come from the same file object, never from three separate path lookups: otherwise a link or junction swapped between them could pair one file’s key with another file’s digest, and the cache would then vouch for the wrong file. super::cache::hash_through opens the file once, stamps that handle, hashes through it, and stamps it again.

On Windows the backend opens the file with sharing for read, write and delete, and reads the key from the handle (GetFileInformationByHandleEx with FileIdInfo, and FSCTL_READ_FILE_USN_DATA).

fn rewind(&self, file: &Self::File) -> Result<(), Self::Error>

Moves file back to its first byte. super::cache::hash_through calls it before every hashing attempt, so a retry after a change reads the whole file again rather than from where the last attempt stopped. A backend that reads by position can do nothing here.
