1//! Content tagging (#44, feature `content-rules`).
2//!
3//! [`scan`] looks for byte patterns in a file and attaches string tags such
4//! as `installer:scripted-setup` or `archive:embedded-pe`. Tags come from
5//! two rule sets:
6//!
7//! - **The built-in set** ([`BUILTIN_TAGS`]), which is read-only. It
8//!   recognises common installer engines, self-extracting archives,
9//!   embedded executables and archives, compiled scripts and the standard
10//!   anti-malware test file. Its tags cannot be redefined.
11//! - **The organisation's rules** ([`RuleSetSource`]), carried in policy.
12//!   A rule is a list of masked byte patterns (hex with nibble wildcards,
13//!   text or wide text), each with a location (anywhere, at an offset, in a
14//!   range, in a PE image's appended data or in the file's tail), and a
15//!   condition (any, all, or at least N of them).
16//!
17//! # A pattern language, not a rule engine
18//!
19//! The rules are deliberately less expressive than a general pattern rule
20//! language: no regular expressions, no gaps of variable length, no loops,
21//! no arithmetic over the file and no modules. Every pattern has a fixed
22//! length of at most [`MAX_PATTERN_LEN`] bytes, so checking it costs at
23//! most that many comparisons. Patterns that are not at a fixed offset are
24//! found through their longest exact run of bytes (an "atom", at least
25//! [`MIN_ATOM_LEN`] bytes) with one multi-pattern automaton
26//! (`aho-corasick`), in a single linear pass. So a scan's cost is linear in
27//! the bytes scanned plus the candidate checks, and both are capped by
28//! [`ScanLimits`].
29//!
30//! The rule format can be targeted by a front end for a general rule
31//! syntax later. A YARA-syntax front end through the `yara-x` crate was
32//! considered and not adopted: every release from 1.22 needs a newer Rust
33//! than the workspace's minimum (1.94), and the last one that builds on
34//! 1.94 brings in a WebAssembly compiler and about 110 more crates, with 37
35//! build scripts (one generating code at build time), and takes the
36//! workspace from 8 to 22 crates in more than one version, over the limit
37//! of 10 (docs/dependencies.md).
38//!
39//! # Never a stall, never an error
40//!
41//! Tagging must not hold up identity, so a scan has a hard budget:
42//!
43//! - Files larger than [`ScanLimits::max_file_size`] (32 MiB by default)
44//!   are scanned in part: the first `max_file_size` bytes and the last
45//!   [`TAIL_SCAN_LEN`]. The report then has [`CONTENT_SCAN_PARTIAL`].
46//! - Scanning stops once [`ScanLimits::max_scan_bytes`] bytes have been
47//!   read, [`ScanLimits::max_match_steps`] pattern comparisons have been
48//!   made, or [`ScanLimits::timeout`] (2 s by default) has passed. The
49//!   report then has [`CONTENT_SCAN_TIMEOUT`].
50//! - A read error, or a file that ends before the length its reader
51//!   reported (truncated while being scanned), ends the scan with
52//!   [`CONTENT_SCAN_ERROR`]. Bytes that did arrive in a chunk are scanned
53//!   first. A short read of the start-of-file filter or the PE headers
54//!   stops at once, because what they decide could not be established.
55//! - A rule's `unless_start` filter is checked before anything else, and a
56//!   filter that could not be checked counts as matched, so a budget or a
57//!   size limit can never let a filtered rule through.
58//!
59//! None of these is an error: [`scan`] always returns a [`TagReport`].
60//! Tags found before the scan stopped are kept, because each is positive
61//! evidence on its own. A missing tag is never evidence of absence when
62//! the report has a status tag. Callers should treat such a file as not
63//! fully inspected and fail conservative: a rule that requires a tag
64//! should not be satisfied by its absence.
65//!
66//! The scan runs in the calling thread and is cooperative: the time limit
67//! is checked before every read, between chunks, every few thousand
68//! candidate checks, on each retry of an interrupted read and after the
69//! last chunk, but it cannot interrupt a `read` or `seek` that blocks. A
70//! scan of a reader that blocks can therefore outlast `timeout`. Running
71//! it off the identity hot path, in a separate worker that can be
72//! abandoned, is the caller's job. That worker is not part of this crate
73//! and is not built yet: the agent's file pipeline (#4, #59, #60) will
74//! provide it, with its scheduling, queueing and cancellation.
75//!
76//! The file is read more than once: the start-of-file filters and the PE
77//! headers are read first, then the file is read again in chunks. A file
78//! rewritten at the same length between those reads can be judged on a mix
79//! of its two versions (a filter decided on the first, strings on the
80//! second), and the scan still reports [`ScanStatus::Complete`]. Callers
81//! that need one consistent view should scan a snapshot, or a file they
82//! hold open with writes denied, as the agent does for hashing.
83//!
84//! # Rule sets in policy
85//!
86//! A [`RuleSetSource`] is plain data (`serde`). It has a version, and
87//! [`ContentRules::rules_digest`] is a SHA-256 over a canonical encoding of
88//! it, so the policy bundle (#43) can record exactly which rules were in
89//! force. The encoding covers the version and every rule as written, with
90//! only the pattern bytes normalised (hex case and spacing); see
91//! [`ContentRules::rules_digest`] for what equal digests mean. The rule set has no signature of its own: it is part of the
92//! policy bundle, whose signature (#225) covers it.

141/// The per-file budget of a scan.
142#[derive(Debug, Clone, Copy, PartialEq, Eq)]
143pub struct ScanLimits {
144    /// Files over this size are scanned in part ([`CONTENT_SCAN_PARTIAL`]).
145    /// Default 32 MiB.
146    pub max_file_size: u64,
147    /// The most bytes read from the reader, counting the start-of-file
148    /// filter and PE header probes, which re-read the first bytes. The
149    /// overlap between chunks is kept in memory, not read again. Default
150    /// 40 MiB, which covers a full scan of a file of `max_file_size`.
151    pub max_scan_bytes: u64,
152    /// The most candidate checks and pattern byte comparisons. Default
153    /// 64 Mi.
154    pub max_match_steps: u64,
155    /// The most wall-clock time, measured from before the first seek and
156    /// checked before every read, between chunks, every few thousand
157    /// candidate checks, on interrupted-read retries and after the last
158    /// chunk. It is cooperative: a `read` or `seek` that blocks is not
159    /// interrupted, so a scan can outlast it (see the module docs). Default
160    /// 2 s. `None` turns it off, so a scan's result depends only on its
161    /// input (for tests and fuzzing).
162    pub timeout: Option<Duration>,
163}
164
165impl Default for ScanLimits {
166    fn default() -> Self {
167        Self {
168            max_file_size: 32 * 1024 * 1024,
169            max_scan_bytes: 40 * 1024 * 1024,
170            max_match_steps: 64 * 1024 * 1024,
171            timeout: Some(Duration::from_secs(2)),
172        }
173    }
174}

176/// The built-in rules and, optionally, the organisation's, compiled.
177///
178/// Compiling checks every limit, so a scan with a compiled set cannot fail.
179/// The value is `Send` and `Sync`, so one compiled set can serve every
180/// worker.
181#[derive(Debug, Clone)]
182pub struct ContentRules {
183    compiled: rules::Compiled,
184    rules_version: Option<u64>,
185    rules_digest: Option<[u8; 32]>,
186}
187
188impl ContentRules {
189    /// Compiles the built-in rules, plus `org` if given.
190    ///
191    /// # Errors
192    ///
193    /// A rule over a limit, with a bad tag or pattern, or reusing a tag.
194    pub fn new(org: Option<&RuleSetSource>) -> Result<Self, RuleError> {
195        Ok(Self {
196            compiled: rules::compile(&builtin::rules(), org)?,
197            rules_version: org.map(|o| o.version),
198            rules_digest: org.map(rules::digest),
199        })
200    }
201
202    /// The organisation rule set's version, if one was given.
203    #[must_use]
204    pub const fn rules_version(&self) -> Option<u64> {
205        self.rules_version
206    }
207
208    /// SHA-256 over a canonical encoding of the organisation rule set, if
209    /// one was given. It covers the set's version and each rule's tag,
210    /// filters, condition, and each string's pattern and location as
211    /// written. Patterns are encoded by the bytes and masks they match, so
212    /// hex case and spacing do not change the digest. Nothing else is
213    /// normalised: two sets that behave the same but are written
214    /// differently, such as `Location::Anywhere` and `Location::From(0)`,
215    /// or the same rules under another version number, have different
216    /// digests. Equal digests mean the same rule set, not just the same
217    /// behaviour.
218    #[must_use]
219    pub const fn rules_digest(&self) -> Option<[u8; 32]> {
220        self.rules_digest
221    }
222
223    /// Every tag a scan can report from a rule, built-in first.
224    pub fn tags(&self) -> impl Iterator<Item = &str> {
225        self.compiled.rules.iter().map(|r| r.tag.as_str())
226    }
227}

229/// How a scan ended.
230#[derive(Debug, Clone, Copy, PartialEq, Eq)]
231#[non_exhaustive]
232pub enum ScanStatus {
233    /// Every byte was scanned.
234    Complete,
235    /// The file is over [`ScanLimits::max_file_size`]; only its start and
236    /// tail were scanned.
237    Partial,
238    /// A budget of [`ScanLimits`] ran out.
239    Timeout,
240    /// The reader failed, or the file ended before the length the reader
241    /// reported (`UnexpectedEof`).
242    ReadError(io::ErrorKind),
243}
244
245impl ScanStatus {
246    /// The status tag added to [`TagReport::tags`], if any.
247    #[must_use]
248    pub const fn tag(self) -> Option<&'static str> {
249        match self {
250            Self::Complete => None,
251            Self::Partial => Some(CONTENT_SCAN_PARTIAL),
252            Self::Timeout => Some(CONTENT_SCAN_TIMEOUT),
253            Self::ReadError(_) => Some(CONTENT_SCAN_ERROR),
254        }
255    }
256}

258/// The result of [`scan`].
259#[derive(Debug, Clone, PartialEq, Eq)]
260pub struct TagReport {
261    /// The tags, in rule order (built-in first), then the status tag, if
262    /// any.
263    pub tags: Vec<String>,
264    /// How the scan ended.
265    pub status: ScanStatus,
266    /// [`BUILTIN_VERSION`].
267    pub builtin_version: u16,
268    /// [`ContentRules::rules_version`].
269    pub rules_version: Option<u64>,
270    /// [`ContentRules::rules_digest`].
271    pub rules_digest: Option<[u8; 32]>,
272    /// The file length, as the reader reported it.
273    pub file_size: u64,
274    /// The PE headers parsed, so rules with
275    /// [`RuleSource::require_pe`] applied.
276    pub is_pe: bool,
277    /// Bytes read.
278    pub bytes_scanned: u64,
279    /// Candidate checks and pattern byte comparisons made.
280    pub match_steps: u64,
281}
282
283impl TagReport {
284    /// Whether the report has `tag`.
285    #[must_use]
286    pub fn has(&self, tag: &str) -> bool {
287        self.tags.iter().any(|t| t == tag)
288    }
289}

291/// Scans a file for content tags. Never fails and never exceeds `limits`;
292/// see the [module documentation](self). The reader is left at an
293/// unspecified position.
294pub fn scan<R: Read + Seek + ?Sized>(
295    reader: &mut R,
296    rules: &ContentRules,
297    limits: &ScanLimits,
298) -> TagReport {
299    scan::run(reader, rules, limits)
300}
301
302/// [`scan`] over bytes held in memory.
303#[must_use]
304pub fn scan_bytes(data: &[u8], rules: &ContentRules, limits: &ScanLimits) -> TagReport {
305    scan(&mut Cursor::new(data), rules, limits)
