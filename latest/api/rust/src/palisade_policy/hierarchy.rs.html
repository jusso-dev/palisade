1//! The group hierarchy, inheritance and the effective policy of a device
2//! (#37).
3//!
4//! A [`HierarchyDocument`] is one snapshot of an installation's scopes:
5//! the tree of nodes, the policies assigned to them, the reusable
6//! [libraries](crate::library) and the automatic placement rules. It is an
7//! immutable value. [`HierarchyDocument::validate`] checks it once and
8//! returns a [`ValidatedHierarchy`], from which
9//! [`ValidatedHierarchy::effective_policy`] computes the one effective
10//! policy of a device. That is a pure function of the snapshot, the
11//! libraries at their resolved versions, and the device's membership of
12//! dynamic groups. The same inputs always give the same policy and the same
13//! content hash, whatever order the snapshot lists anything in.
14//!
15//! The server stores the snapshot, computes and caches effective policies
16//! (#10, #127, #128, #129), and ships them in the bundle (#43). The agent
17//! only ever sees the flattened result.
18//!
19//! # Levels
20//!
21//! | Kind | Parent | Notes |
22//! |---|---|---|
23//! | `global` | none | Exactly one: installation-wide defaults ("global defaults"), visible only to installation administrators. |
24//! | `tenant` | the global node | |
25//! | `group` | a tenant or a group | Nested at most [`limits::MAX_GROUP_DEPTH`] deep below the tenant. |
26//! | `device` | a group | A device has exactly one primary group: its parent. |
27//! | `dynamic_group` | a tenant | Assignment only, not hierarchy: a device's membership is an input ([`Membership`]), computed from tags by #38 and #10. |
28//! | `template` | the global node or a tenant | Not in the tree. A node may link to one (see [Templates](#templates)). |
29//!
30//! Each tenant has the built-in groups `unassigned` (exactly one: new and
31//! unmapped devices; its mode is `audit` unless it sets one), and at most
32//! one each of `unmanaged` (removed from management: the effective policy
33//! is [`Management::Unmanaged`], and the agent goes to `disabled` with
34//! tamper protection released) and `staging` (hidden: no device can be in
35//! it, and placement cannot target it; it is for dry runs with
36//! [`ValidatedHierarchy::effective_policy_as`]). Built-in groups sit
37//! directly below their tenant and have no child groups. Every reference to
38//! a node is checked, and a parent cycle is rejected with its path
39//! (`node_cycle`).
40//!
41//! # Layers
42//!
43//! A device's effective policy is built from layers, from the outermost to
44//! the nearest: the global node, its tenant, its groups from the tenant
45//! down, its dynamic groups (the highest `rank` first, so the lowest rank is
46//! nearest), and the device. A node that links to a template is preceded by
47//! the template's layer at the same position. Within one node, policies are
48//! applied by `slot_order`: the lowest slot wins a conflict.
49//!
50//! # Rules are additive
51//!
52//! A node contributes the rule sets of every policy assigned to it, the
53//! rule set libraries it assigns (`rule_sets`), and every rule set library
54//! in each of its `categories`, including ones added later. The effective
55//! rule list is the union over all layers. Each rule keeps its provenance:
56//! the nodes that contributed it and how ([`RuleProvenance`]). A rule set
57//! that two layers contribute is included once. Two different rule sets
58//! with one ID, including two versions of one library, are rejected
59//! (`rule_set_conflict`, `library_version_conflict`), so a child cannot
60//! pin an older version of an inherited blocklist.
61//!
62//! A child cannot delete an inherited rule. It can:
63//!
64//! - **suppress** it locally, with `suppress_inherited: [rule_id]`, if the
65//!   rule set allows it: `allow_child_suppress`, which defaults to `true`
66//!   for allowlists and baselines and to `false` for every other kind, so
67//!   blocklists cannot be suppressed unless they say so. **A mandatory rule
68//!   set can never be suppressed**, whatever it says (ADR 0004, #125). A
69//!   suppressed rule stays in the effective policy, disabled, and its
70//!   provenance says which node suppressed it. A suppression only applies
71//!   to a rule that every contributing layer is above the suppressing node;
72//!   if the node or a nearer layer also contributes the rule set, the rule
73//!   stays active and is reported as reasserted; or
74//! - **shadow** it with a rule of its own that wins under the precedence
75//!   model. Mandatory denies are evaluated before every model, so nothing
76//!   shadows them.
77//!
78//! # Settings are override-by-nearest
79//!
80//! Each top-level key of [`PolicySettings`](crate::model::PolicySettings)
81//! is one setting. A layer sets a key through its node's `settings` map, or
82//! through an assigned policy whose value for the key differs from the
83//! default; to set a key back to its default below a node that changed it,
84//! use the node's `settings`. A node's own `settings` beat the policies
85//! assigned to it. The nearest layer that sets a key wins. A key in a
86//! node's `locked_settings` keeps the value it has at that node (after the
87//! node's own layers) for every layer below; a later attempt to change it is
88//! ignored and reported (`blocked_by_lock`). Settings added to the model
89//! later are inherited the same way, with no change here.
90//!
91//! The mode options are merged the same way, per key:
92//! `mode_by_type.<type>`, `mode_disconnected` and `disconnected_after_secs`.
93//! `locked_settings` may lock them too, as `mode_options.mode_disconnected`,
94//! `mode_options.disconnected_after_secs` and `mode_options.mode_by_type`
95//! (every type at once).
96//! A `mode_disconnected` that is not at least as strict as the effective
97//! mode is dropped, because unset means the effective mode itself.
98//!
99//! # Modes
100//!
101//! Each layer's mode is its node's `mode`, or else the mode of its
102//! policies, merged by `mode_merge`: `closest` (the default) takes the
103//! policy with the lowest slot, `strictest` the strictest (#36). The
104//! built-in `unassigned` group is `audit` unless it sets a mode. Across
105//! layers, `closest` takes the nearest layer's mode and `strictest` the
106//! strictest of all. With no mode anywhere the device is in `audit`
107//! (ADR 0012).
108//!
109//! A node with `lock_mode: true` fixes a **floor**: the mode in force at
110//! that node. Nothing in the effective policy may then decide in a weaker
111//! mode: a weaker effective mode, `mode_by_type` entry or rule set
112//! `mode_override` is raised to the floor, a control level that would cap
113//! below it is raised (an `enforce` floor needs `enforce`, an `audit` or
114//! `learning` floor at least `audit`), and with an `enforce` floor
115//! `never_enforce` rules become `inherit`. A lock applies to the whole
116//! effective policy, including what the locking node assigns itself. Every
117//! change is listed in [`ModeProvenance::adjustments`]. Raising is always
118//! allowed below a lock.
119//!
120//! # Precedence models
121//!
122//! The model is chosen by the nearest of the global node and the tenant
123//! that sets `precedence`; a group may set it only if its tenant's
124//! `tenant_options.allow_group_precedence` is `true`
125//! (`precedence_not_allowed`). With no node choosing, the model of the
126//! highest-ranked policy (nearest layer, lowest slot) applies. Every policy
127//! in the effective policy must use exactly that model and its options, or
128//! the effective policy is rejected (`precedence_conflict`), so one
129//! effective policy never mixes models.
130//!
131//! # First-match bands
132//!
133//! Under `first_match`, rules are ordered by level before their `order`:
134//! every rule set carries the band of the first layer that contributed it
135//! ([`RuleSet::band`](crate::model::RuleSet::band)). `level_order:
136//! top_down` (the default) puts the global node first, then the tenant, the
137//! groups from the tenant down, the dynamic groups and the device, so a
138//! local administrator cannot pre-empt global policy; `bottom_up` reverses
139//! that; `flat` puts every rule set in band 0, so only `order` counts.
140//! Mandatory denies and exclusions are decided before the model in every
141//! case, and the implicit deny after it.
142//!
143//! # Templates
144//!
145//! A node may be created from a template in two ways. A **one-time copy**
146//! ([`ValidatedHierarchy::copy_from_template`]) copies the template's
147//! assignments, rule sets, categories, settings, mode and suppressions into
148//! a new node, with no link afterwards. A **linked** node sets `template`:
149//! the template's layer is applied at the node's position, just before the
150//! node's own, on every computation, so later changes to the template take
151//! effect. A template cannot link to another template.
152//!
153//! # Explaining
154//!
155//! [`EffectivePolicy::rule`] and [`EffectivePolicy::setting`] return, for
156//! a rule or a setting, every node that contributed it, how, and whether it
157//! was suppressed, reasserted, overridden or blocked by a lock (for #41).
158//!
159//! # Placement
160//!
161//! Each tenant has an ordered list of placement rules (`placement`), see
162//! [`placement`].

221/// One snapshot of the hierarchy.
222#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize)]
223#[serde(deny_unknown_fields)]
224pub struct HierarchyDocument {
225    /// The policy schema version the snapshot was written for.
226    pub schema_version: SchemaVersion,
227    /// Monotonic revision, raised by the server on every change. It is the
228    /// effective policy's revision.
229    pub revision: u64,
230    /// The nodes, in any order.
231    #[serde(default, skip_serializing_if = "Vec::is_empty")]
232    pub nodes: Vec<Node>,
233    /// The policies that nodes assign, in any order.
234    #[serde(default, skip_serializing_if = "Vec::is_empty")]
235    pub policies: Vec<PolicyEntry>,
236    /// Every library version, in any order.
237    #[serde(default, skip_serializing_if = "Vec::is_empty")]
238    pub libraries: Vec<Library>,
239    /// Automatic placement rules, in any order; each tenant's are ranked
240    /// by `order`.
241    #[serde(default, skip_serializing_if = "Vec::is_empty")]
242    pub placement: Vec<PlacementRule>,
243}
244
245impl HierarchyDocument {
246    /// Reads a snapshot from JSON in strict mode, with the reader of
247    /// [`crate::dsl`]: a key repeated at any depth (including inside a
248    /// node's `settings` values) is an error, so JSON and YAML always read
249    /// a snapshot the same way.
250    ///
251    /// # Errors
252    ///
253    /// The reader's error, or the model error, as text.
254    pub fn from_json(input: &str) -> Result<Self, String> {
255        Self::from_yaml(input)
256    }
257
258    /// Reads a snapshot from YAML, with the strict rules of
259    /// [`crate::dsl`] (YAML 1.2, no anchors or tags, no duplicate keys at
260    /// any depth). JSON is YAML here, read by the same strict reader.
261    ///
262    /// # Errors
263    ///
264    /// The reader's error, or the model error, as text.
265    pub fn from_yaml(input: &str) -> Result<Self, String> {
266        let value = crate::dsl::to_json_value(input, &crate::dsl::Limits::default())
267            .map_err(|e| e.to_string())?;
268        serde_json::from_value(value).map_err(|e| e.to_string())
269    }
270}

345    pub id: NodeId,
346    /// Display name, with the same rules as a policy name.

361    #[serde(default, skip_serializing_if = "Vec::is_empty")]
362    pub assignments: Vec<Assignment>,
363    /// Rule set libraries assigned here.
364    #[serde(default, skip_serializing_if = "Vec::is_empty")]

367    /// library in one is assigned here, at its latest version.

370    /// Inherited rules disabled here and below.

373    /// Settings set here: keys of the policy `settings`, with their values.

379    pub locked_settings: Vec<String>,
380    /// The mode set here, beating the policies assigned here.
381    #[serde(default, skip_serializing_if = "Option::is_none")]

384    #[serde(default, skip_serializing_if = "core::ops::Not::not")]

386    /// The precedence model, on the global node, a tenant, or a group whose
387    /// tenant allows it.
388    #[serde(default, skip_serializing_if = "Option::is_none")]
389    pub precedence: Option<PrecedenceSetting>,
390    /// Options of a tenant (or, as defaults, of the global node).
391    #[serde(default, skip_serializing_if = "Option::is_none")]
392    pub tenant_options: Option<TenantOptions>,
393    /// For a dynamic group: its rank among the tenant's dynamic groups. A
394    /// lower rank is nearer the device, so it wins a conflict. Unset is 0.
395    #[serde(default, skip_serializing_if = "Option::is_none")]
396    pub rank: Option<u32>,
397    /// For a group: `false` opts it out of automatic placement, as a source
398    /// (a device in it is never moved) and as a target. Unset is `true`.
399    #[serde(default, skip_serializing_if = "Option::is_none")]
400    pub allow_auto_assignment: Option<bool>,
401}

576            Self::ConflictingScope => "conflicting_scope",
577        }
578    }
579}
580
581impl fmt::Display for HierarchyCode {
582    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
583        f.write_str(self.as_str())
584    }
585}
586
587/// One hierarchy finding: a code, the JSON Pointer of the offending value
588/// in the snapshot (or, for the effective policy, under `/effective`), and a
589/// message.
590#[derive(Clone, Debug, PartialEq, Eq)]
591pub struct HierarchyError {
592    /// The stable code.
593    pub code: HierarchyCode,
594    /// Where.
595    pub path: String,
596    /// What is wrong.
597    pub message: String,
598}
599
600impl fmt::Display for HierarchyError {
601    fn fmt(&self, f: &mut fmt::Formatter<'_>) -> fmt::Result {
602        write!(f, "error[{}] {}: {}", self.code, self.path, self.message)
603    }
604}
605
606impl std::error::Error for HierarchyError {}
607
608pub(crate) fn herr(
609    code: HierarchyCode,
610    path: impl Into<String>,
611    message: impl Into<String>,
612) -> HierarchyError {
613    HierarchyError {
614        code,
615        path: path.into(),
616        message: message.into(),
617    }
618}
