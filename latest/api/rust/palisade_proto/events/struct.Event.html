Expand description

One canonical event.

Field order here is the serialisation order, so Event::to_canonical_json is deterministic.

Fields§

§schema_version: SchemaVersion

The schema version of this event.

§event_id: Uuid7

A unique ID, assigned by the producer.

§event_type: EventType

The registered type, for example exec.decision.

§category: Category

The type’s category. It must match the registry.

§action: Token

The verb, for example execute, load, install or activate.

§outcome: Outcome

What happened.

§severity: Severity

0 to 10. See Severity::syslog for the syslog mapping.

§mode: Option<EventMode>

The enforcement mode, where one applies.

§description: Description

A human-readable description of the event (ISM-0585).

§ts: Timestamp

When the event happened, in UTC.

§ts_agent_monotonic: Option<u64>

The producer’s monotonic clock when the event was recorded, in microseconds since the agent started. It orders events even when the wall clock jumps.

§clock_synced: bool

Whether the producer’s wall clock was synchronised when ts was taken.

§clock_skew_ms: Option<i64>

The producer’s last measured clock offset, in milliseconds.

§tenant_id: TenantId

The tenant.

§host: Host

The device the event is about (ISM-0585: IT equipment).

§user: Option<User>

The user, if any.

§policy: Option<PolicyRef>

The Palisade policy and rule that decided, if known.

§seq: u64

The producer’s sequence number, starting at 0.

§prev_hash: Option<Sha256Hex>

The chain value of the producer’s previous event. Absent only when seq is 0.

§labels: Labels

Labels from policy tags.

§source: Option<Source>

Where the event came from, for events translated from another log.

§process: Option<Process>

The process that acted.

pub fn from_json(input: &str) -> Result<Self, LoadError>

Reads an event from JSON.

The schema version is checked first (check_version), so an event from another version gets a version error rather than a confusing field error. Unknown fields are rejected. This does not run Event::validate.

§Errors

Returns LoadError if the input is not an event this reader understands.

pub fn to_canonical_json(&self) -> Result<String, Error>

The canonical JSON form: compact, fields in schema order, optional fields that are not set left out, labels sorted by key. Equal events have equal canonical forms. This is the form producers send and chain.

§Errors

Only fails if serialisation itself fails, which these types do not do.

pub fn ism_0585_gaps(&self) -> Vec<&'static str>

The ISM-0585 fields this event lacks, by name. Empty when the event records the date and time, the user or process, the file name, a description and the device.

ts, description and host are required by the type, so only the subject and object can be missing. The “file name” is the name of the object acted on: a file path, a script path or inline marker, a packaged app’s name, or, for COM activation, the class ID. Since 1.1 it may also be a network destination (URL, UNC path, remote host name or address), a device (instance ID, friendly name or serial) or a registry key, for decisions about those objects.
