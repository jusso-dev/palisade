The versioned JSON Schema (2020-12) of Event.

The schema is generated from the Rust types and the registry, so it cannot drift from them. The generated text is committed at schemas/events/v{major}.json, and the test committed_schema_is_current fails when the committed file differs from what generate produces. Regenerate it with:

PALISADE_BLESS=1 cargo test -p palisade-proto --test events_schema

Besides the shape of every field, the schema states the cross-field rules that Event::validate checks, so a consumer that only has the schema enforces them too:

  • each event_type fixes its category and the field sets it requires;
  • prev_hash is present exactly when seq is not 0;
  • a script is either a file (path) or inline: exactly one;
  • no field may be null: unset optional fields are left out;
  • an event labelled with an older minor version than a field set, field, event type or source kind it uses is invalid (the since versions);
  • source.format is present exactly when source.kind is third_party;
  • network.resolution needs network.remote_hostname;
  • a registry value has a value_name or is the default_value, not both, and truncated data has a preview;
  • an admin change has exactly the old and new values its op needs.

The $id names the major version only: every minor version of a major is a valid instance of the newest schema for that major (see the compatibility rules in crate::events).
