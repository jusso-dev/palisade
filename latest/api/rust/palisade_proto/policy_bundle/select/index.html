palisade_proto::policy_bundle

Module select 

Source
Expand description

Which bundle the agent runs, and whether a new bundle is accepted.

startup picks what to load from the cache files and the record copies, following the failure table of ADR 0018 (which supersedes ADR 0012) and the startup steps of ADR 0007 (still proposed):

StateLoadEvents
active passes and is at or above the floorActivenone, or policy.signature.invalid if loaded unsigned under audit/warn
active fails; previous verifies and is the recorded fallback, or at or above the floorPreviousthe rejection of active, policy.lkg_loaded
both fail, after a policy was ever acceptedEmergencyeach rejection, policy.emergency_loaded, and tamper.policy.rollback_suspected if the floor rejected a bundle
no policy was ever acceptedFirstInstallnone

Record copies that are missing, corrupt or disagree raise tamper.policy.rollback_suspected, except for the disagreement an interrupted activation leaves (RecordCopies::interrupted_activation). Staleness never changes what loads (super::stale).

pending decides whether a downloaded bundle is activated, and returns the record values to write before and after the rename (ADR 0007 activation steps 1 to 5).

“A policy was ever accepted” (ADR 0018) is: the floor is above zero, an active or previous file exists, or a record copy exists but does not unseal. The last is stricter than the ADR: a corrupt copy is evidence that a record was written, so it never opens the first-install path.
