Module policy_bundle 

Source
Expand description

Policy bundle integrity decisions (part of #225): the anti-rollback record, the signature mode, and which bundle the agent runs.

This module is pure: no storage, no OS calls, no clock reads. The agent (#61 policy cache, #220 tamper protection) supplies the bytes it read and the time, and carries out what the functions here decide. The bundle is opaque until #43 defines it: this module only sees BundleMeta (tenant, target, policy_version and content SHA-256) and the result of the envelope checks the caller ran (Examined).

  • record: the anti-rollback record. It holds the floor (the highest version made active for a target) and the fallback (the version in previous that active directly replaced). Each copy is sealed with HMAC-SHA-256, and record::RecordCopies applies the copy-mismatch rule.
  • SignatureMode: audit, warn or enforce, and the rule that relaxed modes need a dev build or an explicit group opt-in.
  • select: what to run at startup (active, then previous under the one-step exception, then the emergency policy, then first-install audit) and whether a new pending bundle is accepted, following the failure table of ADR 0018 (which supersedes ADR 0012) and the activation order of ADR 0007.
  • stale: staleness, which is reported but never changes what runs.

Every rejection maps to exactly one event type (Rejection::event_type, select::Finding::event_type). None of these functions can return an allow-all outcome: the only non-enforcing result is select::Load::FirstInstall, and it is returned only when the device has never accepted a policy.
