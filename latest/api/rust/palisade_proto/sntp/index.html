Module sntp

The SNTP packet codec (RFC 4330, the client side of RFC 5905): builds a request, checks a reply and computes the clock offset.

The server uses it for its clock health check (#224: warn when the offset from NTP is over 1 s, ISM-0988), and the agent can use it for its trusted-time checks (#220). It does no I/O: the caller sends the request, receives the reply and reads its own clock.

A reply is untrusted network input, so Reply::parse checks every field it uses and refuses everything else:

  • exactly 48 bytes (no extension fields or MAC, which SNTP clients do not use);
  • version 3 or 4, mode 4 (server);
  • leap indicator not 3 (the server’s clock is not synchronised);
  • stratum 1 to 15: 0 is a kiss-o’-death or unspecified, 16 and above unsynchronised;
  • the originate timestamp equals the transmit timestamp of the request, so a reply to someone else’s request, or a replayed one, is refused;
  • receive and transmit timestamps are non-zero, and the server did not send before it received.

NTP timestamps are seconds since 1900 in 32.32 fixed point and wrap every 2^32 seconds (in 2036). Each is placed in the era that puts it closest to the local clock, so the codec keeps working across the wrap as long as the local clock is within 68 years of the truth.
