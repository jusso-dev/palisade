palisade_proto::pki

Module lifecycle 

Source
Expand description

Renewal, rotation and expiry schedules (#224).

These are pure functions of a validity window, the current time and, for renewal, a caller-supplied random number. Nothing here reads a clock or a random source, so every schedule can be tested by time travel.

  • RenewalPolicy: when a device certificate renews (at 2/3 of its lifetime, up to 10% earlier at random), how failed attempts back off (exponentially, up to 6 hours), and when a failing renewal alerts (less than 7 days left).
  • ExpiryAlerts: the console’s expiry alert thresholds (30, 14, 5 and 1 days by default).
  • RotationPlan: a key rotation with overlap: the new key is staged, the service switches to it, and the old key is removed after the overlap. Constructors enforce the minimum overlaps the issue sets for server TLS, issuing CA and unlock-token rotations.
  • Adoption: how many devices report a trust version, which gates retiring an old policy-signing key.

Every rule leans towards keeping the old key longer, or renewing earlier, never the reverse (ADR 0018): a missing fact never shortens an overlap.
