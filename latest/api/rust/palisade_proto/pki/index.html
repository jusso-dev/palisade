Key inventory, signed trust sets and signing for Palisade’s internal PKI (part of #224).

Both the agent and the server need this code: the server builds and signs trust sets, and the agent verifies them. ADR 0003 puts code shared by the sibling binaries in palisade-proto. It cannot go in palisade-core, which has no third-party dependencies and builds no_std for the kernel driver, while signatures need ring (ADR 0008).

  • key: key IDs, purposes, algorithms, the key lifecycle and the device-certificate binding.
  • trust_set: the signed trust-set manifest, its canonical encoding, and the agent’s acceptance rule.
  • signer: the Signer interface and an in-memory software back end.
  • time: validity windows with clock-skew tolerance, and the clock.

Every signature covers a Domain prefix followed by the payload, so a signature made for one purpose can never verify as another (threat: T-signer-02). The only module that calls ring is the crate-private crypto module.
