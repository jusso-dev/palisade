The signed trust-set manifest and the agent’s acceptance rule.

A trust set tells an agent which keys it trusts: the keys that may sign the next trust set, the server CA public-key pins, the policy-signing and unlock-token keys, the signature algorithms it accepts, and a pointer to the update-signing root metadata (#226). It is signed by the offline root or by a trust-set key that an earlier trust set endorsed.

§Acceptance rule

TrustAnchor::accept takes a new signed trust set only if all of these hold (threats: T-signer-06, T-ca-01):

  1. The envelope and manifest decode under the strict rules below.
  2. At least one signature verifies under a key the agent already trusts: the pinned root, or a root-ca or trust-set key in the current trust set. A key listed only in the new set never counts, so a set cannot endorse itself.
  3. A current-set key only counts if its validity window contains now, allowing for clock skew. The pinned root has no window: it is trusted until the device is re-enrolled (R-11).
  4. Every signature by a key the agent knows (the pinned root or a current trust key) must name that key’s own algorithm, an algorithm the current set accepts, and must verify, whether or not the key is inside its validity window. A bad or mislabelled signature from a known key is tampering, not noise, and rejects the whole set. Signatures from unknown keys are ignored, which lets a set carry signatures for agents on different trust versions during a rotation.
  5. trust_version is strictly greater than the current one, so an older or replayed set is refused (rollback), and at most MAX_VERSION_STEP greater. Without the cap, a stolen trust-set key could publish version u64::MAX and no later set, not even one signed by the root, could ever be newer (fast-forward). The cap applies to root-signed sets too, so recovering agents that a stolen key moved far ahead of the rest may need intermediate sets.
  6. issued_at is not earlier than the current set’s, and not later than now plus the skew tolerance.

now must be trusted time on the agent (#220). Storing the accepted set and the last two versions in the protected data directory is also #220.

§Canonical encoding

The signed payload is a fixed-layout binary encoding with one valid encoding per trust set. The decoder enforces that: every list is sorted strictly ascending (so duplicates are refused), every count and length is bounded, every code is known, and no bytes may follow the last field. encode(decode(bytes)) == bytes for every accepted input.

All integers are big-endian. Timestamps are signed 64-bit microseconds since 1970-01-01T00:00:00Z, within years 0001 to 9999.

payload    = version:u8 (= 1)
             trust_version:u64 (>= 1)
             issued_at:i64
             n_algs:u8 (1..=2)   alg:u8 * n_algs          ascending
             n_trust:u8 (1..=64) key * n_trust            ascending kid
             n_pins:u8 (0..=64)  sha256:[u8;32] * n_pins  ascending
             n_policy:u8 (0..=64) key * n_policy          ascending kid
             n_unlock:u8 (0..=64) key * n_unlock          ascending kid
             update_root:u8 (0 | 1)
               [version:u64 sha256:[u8;32]]               if update_root = 1
key        = purpose:u8 status:u8 alg:u8
             not_before:i64 not_after:i64
             spki_len:u8 spki:[u8; spki_len]

envelope   = version:u8 (= 1)
             payload_len:u32 (1..=65536) payload
             n_sigs:u8 (1..=8) sig * n_sigs               ascending kid
sig        = kid:[u8;16] alg:u8 bytes:[u8; length fixed by alg]

Codes are KeyPurpose::code, KeyStatus::code and SignatureAlgorithm::code. A key ID appears at most once across all three key lists, so no key serves two purposes. Each list holds only its own purposes: root-ca or trust-set, then policy-signing, then unlock-token. Listed keys are active or retiring: a retired or compromised key is revoked by leaving it out of the next trust set.

The issue suggests reusing the policy bundle’s canonical CBOR (#225). That encoder does not exist yet. This format is versioned, so a later version can move to it without breaking agents on version 1.
