Source
Expand description

Data-driven mapping of OS-native log records to canonical events (#196).

A mapping file says, for one source log, which canonical EventType each source event ID becomes, with which action, outcome and mode, and which source field fills which canonical field. The shipped files are in crates/palisade-proto/mappings/ and load with MappingSet::builtin.

The input is a decoded Record: the source event ID, the record’s system values, and its event data as a flat map from field name to text. Decoding raw log records into that form, and grouping a decision record with its per-signature records by correlation activity ID, belong to the collector (#58, #90). This module only translates.

§File format

schema_version: 1.1.0          # the event schema version it targets
source: os_security            # a `source.kind`, or `third_party:<format>`
absent_values: ["-"]           # optional: source values that mean "none"
value_maps:                    # optional: named value tables
  logon_type:
    "2": interactive
entries:
  - source_event_id: 3077
    when:                      # optional: the entry applies only if this holds
      field: SISigningScenario
      equals: ["0"]            # or `ends_with: [".sys"]`; case-insensitive
    canonical_type: driver.decision
    action: load
    outcome: blocked
    mode: enforce              # optional
    severity: 7                # optional; default from the registry
    description: The OS code integrity policy blocked a kernel driver.
    field_map:                 # source field: canonical JSON Pointer (or a list)
      FileName: /file/path
      LogonType:               # or a spec:
        to: /user/logon_type   #   the target (or a list)
        values: logon_type     #   optional: translate through a table
        split: ","             #   for set targets: the separator
    set:                       # optional: constants, as text read like a source value
      /script/kind: powershell
    signatures:                # optional: correlated per-signature records
      source_event_id: 3089
      count_field: TotalSignatureCount
      index_field: Signature
      field_map:
        PublisherName: publisher

A when may also be present: true, which holds when the field has a value. Entries for the same source event ID are tried in file order, and the first whose when holds is used. Only the last entry for an ID may omit when, and it is then the fallback.

A source value that is empty or listed in absent_values counts as absent: it fills nothing and matches no when. A value that a table does not list, or that does not fit its target, is dropped and reported in Mapped::dropped; the event is still produced without it.

§Checks when a file is loaded

MappingSet::from_yaml rejects a file, with the entry and field named, when:

  • it is not strict YAML, has unknown keys, or targets another schema major version or a newer minor version;
  • a canonical_type is not registered, or is newer than the file’s schema_version;
  • a target is not a writable canonical field (the table in targets.rs); this is how a mapping that references a field that does not exist fails CI;
  • a target, or the source kind, is newer than the file’s schema_version;
  • a value table is empty, too long, unused, or maps a value to one its target cannot hold; a constant is not a value its target can hold;
  • split is used without a set target, or a set target without split;
  • an entry fills file.signers both directly and from signature records;
  • an entry cannot fill a field set its type requires from its field_map (signer records do not count: an unsigned file has none);
  • a *.decision entry maps none of the subject fields or none of the object-name fields that Event::ism_0585_gaps accepts (ISM-0585);
  • a third_party file joins a set that already translates another format, or a file maps a source event ID another file in the set maps;
  • a when has an empty or repeated value, or a value that an earlier entry for the same event ID and field already matches (so the entry could never apply to it), or an entry follows the fallback.

Every shipped file is loaded by the tests, so these checks run in CI.
